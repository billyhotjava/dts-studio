# T02: 路由优先级集成

**优先级**: P0
**状态**: DONE
**依赖**: T01(匹配引擎)

## 目标

把「已发布指标」接入现有意图路由,作为**最高优先目标**,实现硬优先级分流:

```
已发布指标(高置信) > 视图/mart > 现生成 SQL
```

命中 → 产出指向指标的计划(交 T03 取值);未命中 → 落回原有 `AssetBackedPlannerPolicy` 后续分支(模板/对象图/信号/报表目录/现生成 SQL),行为与接入前完全一致。对应设计 §5 第 2、3 条(优先级硬规则 + 与 sprint-27 乐观执行合流)。

## 技术设计

路由决策中枢是 `dts-copilot-ai/.../service/copilot/AssetBackedPlannerPolicy.java#plan(String userQuestion, Map<String,Boolean> martHealthSnapshot)`,经 `ConversationPlannerService` 调度、结果 `ConversationPlan` 由 `AgentExecutionService` 透传至契约层。F3 在该方法**最前**插入指标分支:

1. **注入 `IndicatorMatcherService`**:在 `AssetBackedPlannerPolicy` 构造函数新增参数(构造注入,与现有 7 个依赖一致;同步更新 `AssetBackedPlannerPolicyTest` 构造)。
2. **指标分支(置于 `plan(...)` 方法体最前,在 `templateMatcherService.match` / `routeWithDataLayer` 之前)**:
   ```
   IndicatorMatchResult im = indicatorMatcherService.match(userQuestion);
   if (im.tier() == HIGH 或 (MEDIUM 且有候选)) {
       return buildPublishedIndicatorPlan(im, ...);  // 命中,交 T03 取值
   }
   // 否则继续走现有所有分支(无任何行为变化)
   ```
   - **高置信单命中** → 直接走指标计划。
   - **多候选 / 中置信** → 仍走指标计划(乐观取最佳),保留候选清单进 plan,供 T03/前端做「按指标X」可切换芯片。
   - **低置信 / NONE** → 不进入指标分支,原样落回后续逻辑。
3. **优先级保证**:指标分支位于模板匹配与 `routeWithDataLayer`(视图/mart 判定)之前,天然实现「指标 > 视图/mart > 现生成 SQL」;现生成 SQL 是 `plan(...)` 末尾的 `BUSINESS_ANALYSIS` 兜底分支,只有指标与上层资产都未命中才到达。
4. **计划承载 `ConversationPlan`**:在 `ConversationPlannerService.ConversationPlan` 与 `ResponseKind` 上扩展,使指标命中可被契约层(T03)与前端识别:
   - `ResponseKind` 新增枚举 `PUBLISHED_INDICATOR`。
   - `buildPublishedIndicatorPlan(...)` 产出 `ConversationPlan`:`mode=AGENT_WORKFLOW`、`responseKind=PUBLISHED_INDICATOR`、`primaryTarget="indicator:" + code`(沿用现有 `ontology:` 前缀风格)、`reportCode=指标 code`、`routedDomain=指标 category 归一域`、`qualityLevel="HIGH"`(高置信)或 `"MEDIUM"`(多候选)、`suggestedDisplay` 复用 `resolveSuggestedDisplayFromQuestion(userQuestion)`、`promptContext` 写入指标口径摘要(name/definition/expressionSql/version)。
   - 指标候选与口径明细通过新增计划字段或 `sourceRefs`/`promptContext` 携带至 T03;`ConversationPlan` 已有的多构造器需补一个重载或复用全参构造器(注意 record canonical 构造器中 `secondaryTargets/qualityNotes/sourceRefs` 已做 `List.copyOf` 防御)。
5. **F1 目录未就绪**:`IndicatorMatcherService` 返回 NONE(T01 已保证),本分支自动跳过,全链路退回现生成 SQL —— 设计 §7「从无缓存 → 指标路由临时禁用,不阻断问数」。
