# T01: 机器账号鉴权 + PlatformIndicatorClient 骨架

**优先级**: P0
**状态**: DONE
**依赖**: 无

## 目标

为 copilot 建立连 dts-platform 的**单受限只读机器账号**鉴权通道与 HTTP 客户端骨架:

- 优先复用 dts-platform 既有服务间认证: `X-DTS-Service: dts-copilot` + `X-DTS-Service-Token`。
- 封装 `PlatformIndicatorClient`,以服务头调 dts-platform `/api/governance/indicators*` 端点;静态 Bearer token / Keycloak client-credentials 保留为 fallback。
- 平台**指标业务零改动**:仅需补 `dts-copilot` 只读服务白名单与部署 token 配置。
- 统一超时与重试策略,所有失败转为结构化结果而非裸异常(为 T04 降级铺路)。

本 Task 只交付**鉴权 + 客户端骨架 + 目录方法**;取值方法在 T04,定时同步在 T02。当前实现先落在 `dts-copilot-analytics`,因为 webapp 的资产库 API 已经通过 analytics BFF 访问;copilot-ai 语义同步仍是后续任务。

## 技术设计

### 配置(application.yml,新增 `copilot.platform.*` 命名空间)

对齐现有 `copilot.action.adminapi.*`(见 `HttpAdminApiActionClient`)与 `dts.copilot.llm.*` 的配置风格,新增:

```yaml
copilot:
  platform:
    indicator:
      base-url: ${PLATFORM_BASE_URL:http://dts-platform:8080}   # 指标端点根
      enabled: ${PLATFORM_INDICATOR_ENABLED:true}
      connect-timeout-seconds: ${PLATFORM_CONNECT_TIMEOUT:5}
      read-timeout-seconds: ${PLATFORM_READ_TIMEOUT:30}
      active-dept: ${PLATFORM_ACTIVE_DEPT:}                      # 可选,透传 X-Active-Dept
    auth:
      token-uri: ${PLATFORM_TOKEN_URI:http://dts-keycloak:8080/realms/S10/protocol/openid-connect/token}
      client-id: ${PLATFORM_CLIENT_ID:dts-copilot-indicator-reader}
      client-secret: ${PLATFORM_CLIENT_SECRET:}                 # 必填,环境变量注入,严禁硬编码
      grant-type: ${PLATFORM_GRANT_TYPE:client_credentials}
```

> 实施纠偏:live 验证发现 dts-platform 当前使用 `PortalOpaqueTokenIntrospector`,不接受 Keycloak client-credentials JWT 作为 portal access token。因此本期改走平台已有服务认证契约;Keycloak client-credentials 仅作为未来用户令牌透传/细粒度权限方案的备选。

### 新增类

1. `service/platform/PlatformIndicatorClient`(`@Component`)
   - 构造注入 `ObjectMapper` + `PlatformTokenProvider` + `@Value` 配置(对齐 `HttpAdminApiActionClient` 写法)。
   - 私有 `get(path, queryParams)`:构造 `HttpRequest`,优先加 `X-DTS-Service`/`X-DTS-Service-Token`;缺失时回退 `Authorization: Bearer`;`IOException`/超时返回结构化失败。
   - 本 Task 实现:`PlatformPage<IndicatorDto> listPublishedIndicators(int page, int size)` → `GET /api/governance/indicators?status=已发布&page=&size=`。
   - 解析 dts-platform 信封:列表端点 payload 形如 `{ data: { content:[...], total, page, size, totalPages } }`(平台 `ApiResponses.ok` 包一层 `data`),客户端剥壳取 `data.content` + 分页字段。

2. `service/platform/IndicatorDto`(copilot 侧轻量镜像 record)
   - 仅映射本期需要的字段:`id, code, name, category, definition, expressionSql, status, version, tags, aggregationType, measureField, dimensionFields, dateColumn, timeGrain, dataLevel, domain, owner`。
   - Jackson `@JsonIgnoreProperties(ignoreUnknown = true)`,平台 DTO 新增字段不影响 copilot。

### 重试与超时

- 连接超时 5s、读超时 30s(配置可调,默认对齐 `HttpAdminApiActionClient`)。
- 对 5xx/401/403/超时**不在本层重试**(交 T02 同步层做整体退避 + T04 降级),避免放大平台负载。

## 影响范围

- **新增**:`dts-copilot-ai/src/main/java/.../service/platform/PlatformTokenProvider.java`、`PlatformIndicatorClient.java`、`IndicatorDto.java`、`PlatformPage.java`(分页结果 record)、`PlatformAuthException.java`。
- **修改**:`src/main/resources/application.yml` 新增 `copilot.platform.*`;`pom.xml` 无需新增依赖(用 JDK `java.net.http` + 已有 Jackson)。
- **dts-platform**:指标业务零改动;服务认证过滤器仅允许 `dts-copilot` 读 `/api/governance/indicators*`,禁止发布/编辑等写操作。
- 不触碰 `SecurityConfiguration` / `ApiKeyAuthFilter`(出站调用,非入站)。

## 验证

- **单元测试**(`PlatformTokenProviderTest`、`PlatformIndicatorClientTest`,JUnit5 + Mockito,可用 `WireMock`/`MockWebServer` 桩 token 端点与指标端点):
  - token 成功获取并缓存,`expires_in` 内复用、过期后重取。
  - `client-secret` 缺失抛 `PlatformAuthException`。
  - `listPublishedIndicators` 正确拼 `status=已发布` 与分页参数,正确剥 `data.content` 信封。
  - 401 触发一次刷新重试;二次仍 401 返回失败结构。
  - 超时/连接拒绝不抛裸异常,返回失败结构。
- **Live contract**(记入 `it/README.md`):在可达 dts-platform 环境,用服务头拉 `PUBLISHED` 指标目录;当前本机通过 `codex_sprint29_live_metric` 本地 fixture 返回 HTTP 200 且 `total=1`。
