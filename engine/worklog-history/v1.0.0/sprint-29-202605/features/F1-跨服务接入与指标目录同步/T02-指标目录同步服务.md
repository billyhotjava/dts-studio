# T02: IndicatorCatalogSyncService 目录同步(定时 + 手动)

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标

新增 `IndicatorCatalogSyncService`,周期性 + 可手动地把 dts-platform 的**已发布指标目录**同步进 copilot:

- 定时(~1h)+ 手动触发,调 `PlatformIndicatorClient.listPublishedIndicators` **分页拉全量** `status=已发布`。
- 结果缓存(**内存为主** + **可选持久化扛重启**),逐指标记录 `version`,口径变更可标记。
- 同步失败采用 **stale-while-revalidate**:保留上次缓存,不清空、不阻断问数(对应设计 D6 / 第 7 节降级)。

> copilot-ai 当前没有任何 `@Scheduled` / glossary 刷新机制(已 grep 确认),本 Task 是定时同步基础设施的真实首次引入。设计中「复用现有 glossary 刷新机制」实际指**复用同类周期刷新范式**(Spring `@Scheduled`),而非已有代码。

## 技术设计

### 启用调度

- 在 `CopilotAiApplication`(或新建 `config/SchedulingConfiguration`)加 `@EnableScheduling`(全局仅需一次)。

### 新增类 `service/platform/IndicatorCatalogSyncService`(`@Service`)

构造注入 `PlatformIndicatorClient` + `IndicatorCatalogStore`(T03 的缓存载体)+ `@Value` 配置。

```yaml
copilot:
  platform:
    indicator:
      sync:
        enabled: ${PLATFORM_INDICATOR_SYNC_ENABLED:true}
        interval-ms: ${PLATFORM_INDICATOR_SYNC_INTERVAL:3600000}   # ~1h
        initial-delay-ms: ${PLATFORM_INDICATOR_SYNC_INITIAL_DELAY:15000}
        page-size: ${PLATFORM_INDICATOR_SYNC_PAGE_SIZE:100}
        max-pages: ${PLATFORM_INDICATOR_SYNC_MAX_PAGES:200}        # 安全上界,防失控分页
```

方法:

- `@Scheduled(fixedDelayString = "${copilot.platform.indicator.sync.interval-ms}", initialDelayString = "...")` 注解 `scheduledRefresh()` → 调 `refresh()`,`enabled=false` 时直接跳过。
- `public SyncResult refresh()`(手动入口,供 T05 BFF 的「立即刷新」端点与启动时调用):
  1. 循环分页 `listPublishedIndicators(page, size)` 直到 `page >= totalPages` 或 `page >= max-pages`,聚合所有 `IndicatorDto`。
  2. 任一页失败 → **整次同步判定为部分失败**:不替换缓存(保留 stale),记 `SyncResult(status=FAILED/PARTIAL, fetched, error)` 并告警日志。
  3. 全量成功 → 转换为 `IndicatorCatalogEntry`(T03 模型),整体 **原子替换** `IndicatorCatalogStore` 快照(copy-on-write,避免读到半截目录)。
  4. 逐指标比对 `code -> version`:若已有缓存中同 `code` 的 `version` 变化,标记 `caliberChanged=true`(供 F5 口径变更提醒),并记日志。
  5. 返回 `SyncResult(status, fetched, added, updated, removed, caliberChanged, lastSyncAt)`。
- `@PostConstruct void warmUp()`:若 `sync.enabled` 且持久化为空,异步触发一次 `refresh()`(不阻塞启动)。

### 缓存与持久化

- **内存**:目录快照存于 `IndicatorCatalogStore`(T03 定义,`volatile` 引用 + `List.copyOf` 不可变快照),读多写少。
- **可选持久化扛重启**:落一份 JSON 快照到 `${DTS_AI_CONFIG_PATH}` 同级目录(对齐 `dts.copilot.ai.config-path` 写法)或新建 Liquibase 表 `copilot_ai.indicator_catalog_snapshot`(单行 JSONB + `last_sync_at`)。本期**默认走文件快照**(简单、扛重启),DB 持久化作为 `persistence-mode` 配置开关的可选项,YAGNI 不强制。
- 重启时:先从持久化加载 stale 快照即时可用,再由 `warmUp()` 后台刷新。

### 可观测

- 每次同步记:抓取条数、耗时、分页数、成功/失败、口径变更数(`log.info`/`log.warn`)。为 F5 可观测埋点预留计数器字段。

## 影响范围

- **新增**:`service/platform/IndicatorCatalogSyncService.java`、`SyncResult.java`(record);`config/SchedulingConfiguration.java` 或在 `CopilotAiApplication` 加 `@EnableScheduling`。
- **修改**:`application.yml` 增 `copilot.platform.indicator.sync.*`;若启用 DB 持久化,新增 Liquibase changelog(`config/liquibase/`)。
- **依赖**:T01 的 `PlatformIndicatorClient`;T03 的 `IndicatorCatalogEntry` / `IndicatorCatalogStore`(可与 T03 并行开发,先用占位接口)。
- **dts-platform**:指标业务零改码;服务认证只读白名单由 F1/T01 统一收口。

## 验证

- **单元测试**(`IndicatorCatalogSyncServiceTest`):
  - 多页分页正确聚合(桩 `PlatformIndicatorClient` 返回 3 页)。
  - 中途某页失败 → 缓存保持上一次快照(stale-while-revalidate),`SyncResult.status` 为 FAILED/PARTIAL。
  - 同 `code` 的 `version` 变更 → `caliberChanged` 标记置位。
  - `enabled=false` 时 `scheduledRefresh` 不发起调用。
  - 原子替换:并发读取永远拿到完整快照(非半截)。
- **集成/手动**(记入 `it/README.md`):启动服务,观察启动后约 `initial-delay` 拉到目录;手动触发刷新成功;重启后从持久化快照即时可读。
