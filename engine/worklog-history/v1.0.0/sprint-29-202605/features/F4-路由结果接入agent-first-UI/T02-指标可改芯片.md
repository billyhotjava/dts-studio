# T02: 指标可改芯片(复用 sprint-27 F5)

**优先级**: P1
**状态**: DONE
**依赖**: T01、sprint-27 F5(`EditableAssumptionChips` + `handleAssumptionCommit` 重算通道)

## 目标

把 F3 命中的指标名渲染为「指标=XX EDIT」**可改假设芯片**;点开后用户可切换其他候选指标,或选「退回 AI 现生成」。整个交互**复用 sprint-27 F5** 已有的 `EditableAssumptionChips` 下拉选择 + `ConversationThread.handleAssumptionCommit` → `handleSendText` 重算通道,由后端 F3 重新路由,**不新造**芯片组件或重算链路。

## 技术设计

F3 命中指标时,按 sprint-27 F8 契约在 `assumptions` 里返回一个「指标」假设项(`CopilotAssumption`,无新增字段):

- `key: "metric"`(或 F3 约定的稳定 key),`label: "指标"`,`value: <命中指标名>`,`editable: true`;
- `options`:候选指标列表(F3 路由的多候选)+ 一个固定项「退回 AI 现生成」(`value` 用一个约定哨兵,如 `__fallback_generated__`,`label: "退回 AI 现生成"`);
- `sourceHint`:命中指标的口径摘要(供芯片 `title` 悬浮提示)。

前端**零改 `EditableAssumptionChips`**:它已支持 `options` → 渲染 `<select>` 下拉(见 `assumptions/EditableAssumptionChips.tsx`),`MessageList.tsx` 已在 `msg.assumptions?.length` 时渲染该组件并把 `onCommit` 透到 `ConversationThread.handleAssumptionCommit`。

- **切候选指标**:用户在下拉选另一候选 → `onCommit("metric", <候选名>)` → `handleAssumptionCommit` 走既有 `handleSendText(sourceQuestion, { assumptionOverrides: { metric: <候选名> }, replaceAssistantMessageId, recomputeArtifactId })`,后端 F3 据 override 重新路由到该指标并回新取值,画布产物原地刷新(T01)。
- **退回 AI 现生成**:选「退回 AI 现生成」哨兵值 → 同一 `handleAssumptionCommit` 通道提交 `assumptionOverrides: { metric: "__fallback_generated__" }`,F3 识别哨兵后跳过指标路由、走现生成 SQL;返回消息无 `trace.metricCaliber` → T01 徽标消失、T03 溯源标「现生成」。
- **乐观执行合流**:沿用 `assumptionConfidence.ts` 的 `OPTIMISTIC_CONFIDENCE_THRESHOLD=0.6` 与 `MessageList` 现有 `shouldExecuteOptimistically(msg.confidence)` 逻辑——高置信单命中直接出芯片可改;低置信/多候选由 F3 给出 `clarifications` 或多 `options`,前端无需新增判定。
- 前端工作量集中在:确认契约映射正确、`__fallback_generated__` 哨兵的前端常量定义与展示文案,以及命中场景下芯片与 T01 徽标的视觉协调。哨兵常量放 `platformIndicatorHit.ts`(T01 新增模块)共享。
