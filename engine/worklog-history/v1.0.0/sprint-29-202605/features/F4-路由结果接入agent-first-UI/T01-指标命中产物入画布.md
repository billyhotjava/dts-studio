# T01: 指标命中产物入对话/画布

**优先级**: P1
**状态**: READY
**依赖**: F2(`type:'indicator'` 产物类型 + 渲染底座)、F3(后端路由命中结果)

## 目标

消费 F3 路由命中响应里的**指标取值 + 溯源**,把命中指标渲染为 `type:'indicator'` 产物 upsert 进活产物画布(复用 F2),并在对话脊柱里给该助手消息标注「来自平台指标」,让用户一眼区分这是权威指标答案而非 AI 现生成。

## 技术设计

判定「指标命中」的依据(来自 F3,无新增契约):助手消息的 `trace.metricCaliber` 存在且带 `name`(命中指标名)。以此派生一个纯函数 `isPlatformIndicatorHit(message)`,集中判定,避免在多处散落 `trace?.metricCaliber?.name` 判断。

- **产物入画布**:`useCopilotStream.ts` 的 `upsertArtifactFromDoneEvent` 当前仅在 `generatedSql/templateCode/reportCode` 存在时 upsert。扩展为:当 done 事件命中指标(`trace.metricCaliber.name` 存在,且 F3 在 done 事件带回指标取值序列/明细)时,走 F2 的 `artifactFromMessage` 分支产出 `type:'indicator'` 产物(F2 已扩展 `artifact.ts` 支持该类型与 `spec.indicator` 元数据块 + `dataset`)。复用既有 `recomputeArtifactId`/`existingArtifact` 逻辑,使切候选/重算时**同 id 原地刷新**取值,不新增产物。
- **对话标识**:`MessageList.tsx` 在助手消息渲染时,若 `isPlatformIndicatorHit(msg)`,在消息内容区上方渲染一个轻量徽标「来自平台指标」(指标名取 `msg.trace.metricCaliber.name`,口径版本取 `version`)。徽标只读、非交互(切换交互归 T02 芯片),与现有 `copilot-chat__generated-report` 通知块同级摆放。
- **来源信息全部取自 F3 的 `trace.metricCaliber`**,前端不二次推断、不重算口径。
- 新增小工具模块 `src/components/copilot/platformIndicatorHit.ts`(`isPlatformIndicatorHit` + 徽标展示模型),便于 T02/T03 共享同一判定。

## 影响范围

- `dts-copilot-webapp/src/components/copilot/MessageList.tsx`(命中消息渲染「来自平台指标」徽标)

## 完成标准

- [ ] 命中指标的取值在画布渲染为 `type:'indicator'` 产物(复用 F2),切候选/重算原地刷新同一产物。
- [ ] 对话内命中消息有「来自平台指标」徽标,信息源自 `trace.metricCaliber`,前端不重算。
- [ ] 未命中(退回现生成)消息不显示该徽标,行为与现状一致。
