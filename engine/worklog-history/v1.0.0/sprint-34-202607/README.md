# Sprint-34: NL2SQL 数据准确性证据链产品化

**时间**: 2026-07
**前缀**: QA (Query Accuracy)
**状态**: DONE
**目标**: 让每一次 NL2SQL 查询都能输出可审计的准确性证据，做到“能执行”之外还能说明意图、口径、数据层、模型和结果对账是否可信。

## 背景

最近的财务凭证统计问题暴露出一个共性风险：SQL 能生成并执行，并不代表数据准确。NL2SQL 结果必须能回答五个问题：

> 术语说明：本 Sprint 使用“权威基准/对账基准”表示权威答案源，不是 Oracle 数据库。应用数据库仍是 MySQL；统计查询应走入湖后的 dbt/DWS/ADS。旧 `oracle*` 字段仅作为 Sprint-33 兼容别名保留。

1. 用户意图是否理解正确。
2. SQL 是否走了正确数据层和业务口径。
3. 底层 ODS/dbt/DWS/ADS 是否新鲜、可用、可追溯。
4. 执行结果是否能和上游或权威基准对账。
5. 用户是否能看懂可信度和低可信原因。

Sprint-31 已做口径单一事实源，Sprint-32 已做路由阶梯，Sprint-33 已在财务域做可证明正确性。本 Sprint 把这些能力收敛成通用 NL2SQL 准确性框架，供财务、采购、库存、报花等域复用。

## 准确性等级

| 等级 | 判定条件 | 用户侧含义 |
|------|----------|------------|
| HIGH | 命中受控模板/指标 + ADS/DWS + dbt/入湖健康 + 对账/不变量通过 | 可直接用于经营判断 |
| MEDIUM | 走 ADS/DWS 且 SQL 可执行，但缺少完整对账证据 | 可参考，需显示缺失证据 |
| LOW | 自由生成或弱路径联邦查询，仅有 schema/执行校验 | 只能作为探索结果 |
| UNTRUSTED | L0 profile、应用库直连、数据未入湖、模型未构建、异常或口径冲突 | 不应展示为统计结论 |

## 本 Sprint 不做

- 不新增或提交 dts-stack dbt 模型源码；dbt 模型包仍以 `worklog/prs/v1` 交付。
- 不重写已有 NL2SQL 路由器，只在现有模板、路由 telemetry、执行结果上补准确性证据。
- 不把所有自由 NL2SQL 一刀切禁用；低可信路径允许探索，但必须降级展示。
- 不改 adminapi 业务逻辑；业务系统只作为只读权威基准或对账基准。

## 完成标准

- [x] 所有 NL2SQL 同步/流式响应都有 `accuracyEvidence` 契约。
- [x] HIGH/MEDIUM/LOW/UNTRUSTED 的评分规则可机器判定，且有原因列表。
- [x] L0 profile、应用 MySQL 直连不能被标为 HIGH；freshness snapshot 和 live dts-platform/dbt diagnostics 探针均能把未构建 ADS/入湖缺失降为 `UNTRUSTED`。
- [x] 财务凭证、财务年度、报花订单至少 3 条代表性问题进入黄金集。
- [x] 每条黄金集用例能校验模板/指标命中、目标数据层、SQL 片段、对账证据。
- [x] 黄金集 scorecard 可输出带运行时间、release gate、失败摘要和弱路径来源的发布证据。
- [x] 用户界面显示数据来源、可信度和缺失证据；低可信会阻断 UNTRUSTED 的确定统计展示并给出入湖/dbt/对账建议。
- [x] `it/README.md` 记录可重跑验证命令和结果。
