# T02: 低可信降级与追问

**优先级**: P1
**状态**: DONE
**依赖**: T01

## 目标

当准确性证据不足时，系统主动降级为澄清、建模建议或对账建议，而不是给出确定结论。

## 技术设计

- LOW：展示探索结果，并提示“建议构建 ADS/补对账”。
- UNTRUSTED：不展示统计值，给出阻断原因。
- 缺参数：走现有 clarification flow。
- 缺模型：生成候选 dbt/ADS 工作项或引导上传 worklog/prs/v1 包。

## 影响范围

- chat response renderer。
- clarification flow。
- low confidence policy。

## 落地结果

- `MessageList` 会读取 `accuracyEvidence.grade`，LOW/UNTRUSTED 显示“可信度不足”提示。
- UNTRUSTED 不再展示“来自平台指标”徽标，也不展示平台指标/SQL 结果预览。
- 低可信提示优先展示 `warnings` 和 `reasons`，把“先入湖/dbt 构建/补对账”作为用户可操作建议。

## 验证

- [x] L0 profile 不输出“来自平台指标”的确定统计结论。
- [x] 未入湖/未构建时提示先执行入湖或 dbt 构建。
- [x] 参数缺失时追问而不是猜测。

## 完成标准

- [x] 低可信路径对用户诚实、可操作、不误导。
