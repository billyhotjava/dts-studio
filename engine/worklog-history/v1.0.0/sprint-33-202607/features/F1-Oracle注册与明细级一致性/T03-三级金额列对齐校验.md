# T03: 三级金额列对齐校验

**优先级**: P0
**状态**: DONE
**依赖**: T02

## 目标

财务最易错的是"选错金额列"（口径铁律#3）。专门校验 copilot 在明细与汇总中对三级金额列的归属与应用系统一致，防止名义/应收/折后/已回款互串。

## 技术设计

- 四列语义锚定（来自 a_month_accounting）：
  - `*_total_amount`（名义）
  - `*_receivable_total_amount`（应收折前）
  - `folding_after_total_amount`（折后实收）
  - `total_amount`（已回款）
- 校验：copilot 回答中"应收/实收/已回款"分别映射到正确列，与 oracle 端点同名口径一致。
- **折扣=1 陷阱**：构造折扣=1（四列相等）与折扣≠1（四列分化）两类样本，确保 copilot 在折扣≠1 时仍选对列（折扣=1 时相等会掩盖错误）。
- 接 Sprint-31 口径规则：三级金额列语义作为结构化标注驱动。

## 落地

- 新增 `FinanceAmountColumnAlignmentRegistry`，加载 `governance/finance-amount-column-alignment.v1.json`。
- 新增 `FinanceAmountColumnAlignmentService`，校验“请求语义 → 选中字段 → oracle 金额”的一致性。
- 机器化四层金额：
  - 名义租金：`receivable_total_amount` / `receivableTotalAmount` / `名义租金`
  - 应收折前：`net_receipt_total_amount` / `netReceiptTotalAmount` / `应收折前`
  - 折后实收：`folding_after_total_amount` / `foldingAfterTotalAmount` / `折后实收`
  - 已回款：`total_amount` / `totalAmount` / `已回款`
- “应收”作为含糊词，必须拆成应收折前/折后实收/已回款，不能静默选列。
- 折扣=1 且四列金额相等时，样本只能判定为 `inconclusive`，不能当成对齐通过证据。
