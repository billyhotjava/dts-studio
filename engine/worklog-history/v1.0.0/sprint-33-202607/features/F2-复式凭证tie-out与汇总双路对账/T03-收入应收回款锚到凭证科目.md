# T03: 收入/应收/回款锚到凭证科目

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: T01, T02

## 目标

把 copilot 的收入/应收/回款汇总 tie-out 到已过账凭证的对应科目，形成会计级闭环证明——汇总不仅"自洽"，而且与账面凭证一致。

## 技术设计

- 建立 报表口径 → 凭证科目 映射（T01 产出延伸）：
  - 已回款 ↔ 收款凭证（结算来源）借贷科目
  - 应收/折后实收 ↔ 结算凭证
  - 采购报销付款 ↔ 付款凭证
- **tie-out**：copilot 汇总值与对应凭证科目借/贷合计在 业务单/账期 粒度相等。
- **跨链校验**：售赠坏链收入与凭证；坏账 receivable 锚到损失科目而非收入（铁律#2，坏账不是收入）。
- 差异分类：时间切口差（未过账）/口径差/真错，分别处置。

## 影响范围

- 对账 harness 增凭证 tie-out 维度
- 产出 `assets/voucher-tieout-mapping.md` 完整映射 + 证据

## 当前进度

- 已落地 `FinanceVoucherSubjectTieoutRegistry`：机器化读取 `finance-voucher-subject-tieout.v1.json`，并强制绑定到 `FinanceOracleRegistry` 的 `voucher-ledger` L3 oracle。
- 已落地 `FinanceVoucherSubjectTieoutService`：按 `voucherBusinessType + businessCode + accountPeriod` 将 copilot 汇总指标与凭证科目借/贷侧合计对齐，支持差异、缺凭证格、链路/指标错配、重复汇总格子的失败输出。
- 已固化 3 组可替换样本科目映射：`settlement-discounted-receivable`、`sale-receivable`、`bad-debt-loss`，其中坏账明确锚到损失科目，防止计入收入。
- adminapi/adminweb 证据已核对：`VoucherController.getcountItems` / `VoucherItemService.getCountItems` 提供科目借贷汇总，`adminweb/src/views/flower/finance/voucher/summary.vue` 使用同一接口展示科目树借/贷金额。
- 未完成：`subjectIds` 仍是本地可替换样本科目组，真实财务科目树/科目 ID 需要 live 环境和财务签字确认；尚未执行真实业务单/账期的 L3 凭证双路取数。
