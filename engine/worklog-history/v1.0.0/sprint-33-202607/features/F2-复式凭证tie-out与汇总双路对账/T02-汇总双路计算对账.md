# T02: 汇总双路计算对账

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F1-T02

## 目标

同一汇总用两条独立路径算，比对差异：copilot NL2SQL 一路，oracle 报表端点（或财务签字的"黄金 SQL"）一路。差异为 0 才采信。

## 技术设计

- **对账对象**：月对账折后实收/已回款汇总（按项目/月）、售账收入汇总、开票/收款汇总。
- **两路**：
  1. copilot：对同一问题/口径生成 SQL 取汇总。
  2. oracle：调 L2 端点（如 `getMonthSettlementData`）或固化的黄金 SQL（升级 Sprint-30 `f4_finance_adminweb_reconciliation.sql`，基准从 L1 表抬到 L2 输出）。
  3. 应用 MySQL oracle：对可签字的问题补一条直接查询应用库 MySQL 原始业务表的只读 SQL，用来证明 ADS/NL2SQL 结果不是靠 ODS 绕路凑数。
- **比对**：按维度（项目×月）FULL JOIN，输出逐格差异（沿用 sprint-30 对账 SQL 的 diff 列风格）。
- **容差**：到分；非零差异即缺陷或登记口径差异。
- **链分离**：租摆链与售赠坏链分别对账，绝不合并 SUM（铁律#2）。

## 影响范围

- 升级/扩展 `it/sql/` 财务对账 SQL（基准 L1→L2）
- 产出 `it/test_f2_summary_dual_reconciliation.sh` + 证据

## 当前进度

- 已落地 `FinanceSummaryDualReconciliationService`：按 `chain + metricId + dimensionKeys` 对 copilot/oracle 两路汇总格子做 FULL JOIN 式比较，金额差异精确到分。
- 已落地 `FinanceSummaryDualReconciliationRegistry`：汇总 case 必须绑定到 `FinanceOracleRegistry` 已登记的 oracle binding，链路不一致会拒绝加载。
- 已固化两个离线黄金 SQL case：`month-settlement-discounted-receivable`（租摆月对账折后实收，项目×账期）与 `sale-account-receivable`（售账应收，项目×账期）。
- 已补静态保护：售账汇总 SQL 使用 Trino 兼容 `date_format(CAST(... AS timestamp), '%Y%m')`，避免回退到 MySQL `DATE_FORMAT` 方言。
- 已新增三类应用 MySQL oracle SQL case：`month-settlement-discounted-receivable`、`sale-account-receivable`、`voucher-year-2026-count`；copilot 侧只读 ADS（`public.xycyl_ads_finance_month_settlement`、`public.xycyl_ads_sale_account_summary`、`public.xycyl_ads_finance_voucher_monthly`），oracle 侧只读查询应用库原表（`a_month_accounting`、`a_sale_account` + `t_flower_biz_info`、`f_voucher`），不允许 `public.ods_*`、`mysql.rs_cloud_flower.*`、JDBC URL 或密码进入清单。
- 已完善 `dts-copilot/worklog/prs/v1/xycyl-finance-dbt-models-v1.zip`：月对账 ADS 增加 `projectId`，补齐售账 ODS/STG/DWD/DWS/ADS 链路和 `models.tsv` manifest；`dts-stack` 不存放模型文件，只由界面导入/构建该包。
- 已新增 `FinanceApplicationMysqlOracleProofService`：把 copilot 结果与应用 MySQL SQL 结果统一成 `chain + metricId + accountPeriod + amount` 汇总格子，复用 `FinanceSummaryDualReconciliationService` 输出差异。
- 已新增 `FinanceApplicationMysqlOracleJdbcQueryExecutor` + 条件化配置 `copilot.finance.application-mysql-oracle.*`：默认不启用；显式配置应用 MySQL JDBC 后，才能直接执行应用库只读 oracle SQL，避免误用平台主库连接。
- 已新增应用内 proof runner 与 REST 入口：`GET /api/ai/finance/application-mysql-oracle/cases` 可列出证明用例，`POST /api/ai/finance/application-mysql-oracle/prove` 可在配置 copilot ADS JDBC 与应用 MySQL JDBC 后直接跑 ADS vs 应用原表 SQL 对账；未配置运行连接时返回 `DISABLED`，避免伪造通过。
- 已修正 planner 优先级窄场景：当年度凭证统计已命中可执行 ADS 模板 `TPL-57` 时，平台指标候选 `prs.finance.voucher.profile` 这类 L0 business-object profile 不再抢走路由，避免再次进入 `L0_BUSINESS_OBJECT_PROFILE` 后由平台指标链路抛 `InterruptedException`。
- 已补强本地 live proof 脚本：`test_f2_application_mysql_oracle_runtime_live_local.sh` 默认用当前已构建的凭证 ADS seed 临时 MySQL 并返回 `PASSED`；通过 `COPILOT_FINANCE_PROOF_CASE_IDS=all` 或逗号分隔 case 列表可覆盖月对账、售账、凭证三类应用 MySQL SQL。若对应 ADS 表未构建或无 2026 数据，脚本会在重启服务前明确失败，不再落到 `/prove` 500 或伪造通过。
- 已新增 registered datasource proof 脚本：`test_f2_application_mysql_oracle_runtime_registered_datasource.sh` 从 `copilot_ai.data_source` 读取已登记应用 MySQL；当默认 `ptr_mysql` 登记密码为空时，回退到 `dts_platform.ingestion_task(ptr_mysql_flow)` + Airflow 任务变量，使用当前 ADS Postgres 运行环境跑同一个 `/prove`。默认 `ptr_mysql` 已返回 `PASSED`；`园林业务库` 仍作为可达但非同源反例保留。
- 已修正凭证应用 MySQL oracle SQL 真实口径：真实应用库 `account_priod` 是 `YYYYMM`，dbt STG 规范成 `YYYY-MM`；凭证月度 `voucher_count` 按有效凭证头计数，不应被 `f_voucher_item` inner join 过滤。当前 `ptr_mysql`、ODS、DWS、ADS 分月均为 `1/96/173/212/181`，差异为 0。
- 已补强运行期异常处理：JDBC/SQL 执行异常不再冒泡成 HTTP 500，而是返回可审计的 `FAILED` 状态和失败消息。
- 未完成：真实 L2 汇总端点或财务签字黄金 SQL 尚未接入；当前运行态 PG 尚缺 `xycyl_ads_finance_month_settlement` 与 `xycyl_ads_sale_account_summary`，全量三 case live proof 需先通过界面构建 dbt 包。
