# T02: 汇总双路计算对账

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F1-T02

## 目标

同一汇总用两条独立路径算，比对差异：copilot NL2SQL 一路，oracle 报表端点（或财务签字的"黄金 SQL"）一路。差异为 0 才采信。

## 技术设计

- **对账对象**：月对账折后实收/已回款汇总（按项目/月）、售账收入汇总、开票/收款汇总。
- **两路**：
  1. copilot：对同一问题/口径生成 SQL 取汇总。
  2. oracle：调 L2 端点（如 `getMonthSettlementData`）或固化的黄金 SQL（升级 Sprint-30 `f4_finance_adminweb_reconciliation.sql`，基准从 L1 表抬到 L2 输出）。
- **比对**：按维度（项目×月）FULL JOIN，输出逐格差异（沿用 sprint-30 对账 SQL 的 diff 列风格）。
- **容差**：到分；非零差异即缺陷或登记口径差异。
- **链分离**：租摆链与售赠坏链分别对账，绝不合并 SUM（铁律#2）。

## 影响范围

- 升级/扩展 `it/sql/` 财务对账 SQL（基准 L1→L2）
- 产出 `it/test_f2_summary_dual_reconciliation.sh` + 证据

## 当前进度

- 已落地 `FinanceSummaryDualReconciliationService`：按 `chain + metricId + dimensionKeys` 对 copilot/oracle 两路汇总格子做 FULL JOIN 式比较，金额差异精确到分。
- 已落地 `FinanceSummaryDualReconciliationRegistry`：汇总 case 必须绑定到 `FinanceOracleRegistry` 已登记的 oracle binding，链路不一致会拒绝加载。
- 已固化两个离线黄金 SQL case：`month-settlement-discounted-receivable`（租摆月对账折后实收，项目×账期）与 `sale-account-receivable`（售账应收，项目×账期）。
- 已补静态保护：售账汇总 SQL 使用 Trino 兼容 `date_format(CAST(... AS timestamp), '%Y%m')`，避免回退到 MySQL `DATE_FORMAT` 方言。
- 未完成：真实 L2 汇总端点或财务签字黄金 SQL 尚未接入；当前只是可重跑的本地 comparator + case contract，不等同于 live 双路取数证明。
