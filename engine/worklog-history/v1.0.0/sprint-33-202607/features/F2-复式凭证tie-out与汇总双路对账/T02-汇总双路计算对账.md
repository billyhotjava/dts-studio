# T02: 汇总双路计算对账

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F1-T02

## 目标

同一汇总用两条独立路径算，比对差异：copilot NL2SQL 一路，权威基准报表端点（或财务签字的"黄金 SQL"）一路。差异为 0 才采信。

## 技术设计

- **对账对象**：月对账折后实收/已回款汇总（按项目/月）、售账收入汇总、开票/收款汇总。
- **两路**：
  1. copilot：对同一问题/口径生成 SQL 取汇总。
  2. 权威基准：调 L2 端点（如 `getMonthSettlementData`）或固化的黄金 SQL（升级 Sprint-30 `f4_finance_adminweb_reconciliation.sql`，基准从 L1 表抬到 L2 输出）。
  3. 应用 MySQL 权威基准：对可签字的问题补一条直接查询应用库 MySQL 原始业务表的只读 SQL，用来证明 ADS/NL2SQL 结果不是靠 ODS 绕路凑数。
- **比对**：按维度（项目×月）FULL JOIN，输出逐格差异（沿用 sprint-30 对账 SQL 的 diff 列风格）。
- **容差**：到分；非零差异即缺陷或登记口径差异。
- **链分离**：租摆链与售赠坏链分别对账，绝不合并 SUM（铁律#2）。

## 影响范围

- 升级/扩展 `it/sql/` 财务对账 SQL（基准 L1→L2）
- 产出 `it/test_f2_summary_dual_reconciliation.sh` + 证据

## 当前进度

- 已落地 `FinanceSummaryDualReconciliationService`：按 `chain + metricId + dimensionKeys` 对 copilot/权威基准两路汇总格子做 FULL JOIN 式比较，金额差异精确到分；失败信息使用 `authority` 文案。
- 已落地 `FinanceSummaryDualReconciliationRegistry`：汇总 case 必须绑定到 `FinanceAuthorityRegistry` 已登记的 authority binding，链路不一致会拒绝加载。
- 已固化两个离线黄金 SQL case：`month-settlement-discounted-receivable`（租摆月对账折后实收，项目×账期）与 `sale-account-receivable`（售账应收，项目×账期）。
- 已补静态保护：售账汇总 SQL 使用 Trino 兼容 `date_format(CAST(... AS timestamp), '%Y%m')`，避免回退到 MySQL `DATE_FORMAT` 方言。
- 已新增三类应用 MySQL 权威基准 SQL case：`month-settlement-discounted-receivable`、`sale-account-receivable`、`voucher-year-2026-count`；canonical 结构化资产为 `dts-copilot-ai/src/main/resources/governance/finance-application-mysql-authority-sql.v1.json`，旧 `finance-application-mysql-oracle-sql.v1.json` 仅作兼容资产；copilot 侧只读 ADS（`public.xycyl_ads_finance_month_settlement`、`public.xycyl_ads_sale_account_summary`、`public.xycyl_ads_finance_voucher_monthly`），权威基准侧只读查询应用库原表（`a_month_accounting`、`a_sale_account` + `t_flower_biz_info`、`f_voucher`），不允许 `public.ods_*`、`mysql.rs_cloud_flower.*`、JDBC URL 或密码进入清单。
- 已完善 `dts-copilot/worklog/prs/v1/xycyl-finance-dbt-models-v1.zip`：月对账 ADS 增加 `projectId`，补齐售账 ODS/STG/DWD/DWS/ADS 链路和 `models.tsv` manifest；`dts-stack` 不存放模型文件，只由界面导入/构建该包。
- 已新增 `FinanceApplicationMysqlAuthorityRegistry`：作为应用 MySQL 权威基准 SQL 的 Spring 主 registry，加载 `finance-application-mysql-authority-sql.v1.json`；旧 `FinanceApplicationMysqlOracleRegistry` 仅保留 deprecated 代码兼容外壳，不再作为 Spring service bean。
- 已新增 `FinanceApplicationMysqlAuthorityProofService`：把 copilot 结果与应用 MySQL SQL 结果统一成 `chain + metricId + accountPeriod + amount` 汇总格子，复用 `FinanceSummaryDualReconciliationService` 输出差异；旧 `FinanceApplicationMysqlOracleProofService` 仅保留 deprecated 兼容外壳，不再作为 Spring service bean。
- 已新增 `FinanceApplicationMysqlAuthorityJdbcConfiguration` + `FinanceApplicationMysqlOracleJdbcQueryExecutor`：推荐使用 canonical 配置 `copilot.finance.application-mysql-authority.*` / `COPILOT_FINANCE_APPLICATION_MYSQL_AUTHORITY_*`，并暴露 `financeApplicationMysqlAuthority*JdbcQueryExecutor` 主 bean；旧 `application-mysql-oracle` / `*_ORACLE_*` 配置和 `financeApplicationMysqlOracle*JdbcQueryExecutor` bean name 仅作兼容回退。默认不启用；显式配置应用 MySQL JDBC 后，才能直接执行应用库只读权威基准 SQL，避免误用平台主库连接。
- 已新增应用内 proof runner 与 `FinanceApplicationMysqlAuthorityProofResource` REST 主入口：推荐 `GET /api/ai/finance/application-mysql-authority/cases`、`POST /api/ai/finance/application-mysql-authority/prove`；旧 `FinanceApplicationMysqlOracleProofResource` 与 `/api/ai/finance/application-mysql-oracle/*` 仅作为 deprecated/兼容 alias。`/cases` 响应推荐读取 `authorityBindingId`，旧 `oracleBindingId` 仅为兼容字段；`/prove` reports 推荐读取 `authoritySource`，旧 `oracleSource` 仅为兼容字段。运行结果、scorecard failure、JDBC 安全异常和 registry 加载日志均使用 `authority proof / authority SQL` 文案，避免把应用 MySQL 权威基准误解为 Oracle 数据库。配置 copilot ADS JDBC 与应用 MySQL JDBC 后可直接跑 ADS vs 应用原表 SQL 对账；未配置运行连接时返回 `DISABLED`，避免伪造通过。
- 已新增 `FinanceApplicationMysqlAuthorityScorecardCheckService`：把应用 MySQL proof runner 的 `PASSED/FAILED/DISABLED` 结果转换成 F4 scorecard 的 `f2-summary-voucher` lane，checkId 使用 `application-mysql-authority-proof`；`DISABLED` 会输出 `PENDING_LIVE_EVIDENCE`，不会伪造成通过；旧 `FinanceApplicationMysqlOracleScorecardCheckService` 仅保留 deprecated 兼容外壳。
- 已修正 planner 优先级窄场景：当年度凭证统计已命中可执行 ADS 模板 `TPL-57` 时，平台指标候选 `prs.finance.voucher.profile` 这类 L0 business-object profile 不再抢走路由，避免再次进入 `L0_BUSINESS_OBJECT_PROFILE` 后由平台指标链路抛 `InterruptedException`。
- 已补强本地 live proof 脚本：`test_f2_application_mysql_authority_runtime_live_local.sh` 默认用当前已构建的凭证 ADS seed 临时 MySQL 并返回 `PASSED`；通过 `COPILOT_FINANCE_PROOF_CASE_IDS=all` 或逗号分隔 case 列表可覆盖月对账、售账、凭证三类应用 MySQL SQL。若对应 ADS 表未构建或无 2026 数据，脚本会在重启服务前明确失败，不再落到 `/prove` 500 或伪造通过。
- 已补强 registered datasource proof 脚本：`test_f2_application_mysql_authority_runtime_registered_datasource.sh` 从 `copilot_ai.data_source` 读取已登记应用 MySQL；当默认 `ptr_mysql` 登记密码为空时，回退到 `dts_platform.ingestion_task(ptr_mysql_flow)` + Airflow 任务变量，使用当前 ADS Postgres 运行环境跑同一个 `/prove`。`COPILOT_FINANCE_PROOF_CASE_IDS=all` 已对月对账、售账、2026 凭证三条 case 返回 `PASSED`；脚本 contract 锁定多 case 不会退化为只跑默认凭证 case。

- 已补强运行期异常处理：JDBC/SQL 执行异常不再冒泡成 HTTP 500，而是返回可审计的 `FAILED` 状态和失败消息。
