# T02: 持续对账记分卡

**优先级**: P1
**状态**: IN_PROGRESS
**依赖**: T01

## 目标

把 L1–L3 对账集 + 不变量检查 + 差分网格汇成一张每日/按需可跑的记分卡,使财务正确性成为**持续监控的属性**而非一次性声明。

## 技术设计

- **记分卡内容**：
  - 明细对账通过率（F1）、汇总/凭证 tie-out 通过率（F2）、不变量通过率（F3）、差分网格通过率（T01）。
  - 逐项差异明细（报表/维度/差额）。
  - **漂移**：与上次基线比，新增差异即漂移告警。
- **运行**：可手动 + 定时（CI/调度），输出结构化报告 + 健康端点字段。
- **容差策略**：财务金额到分;非零差异分类为 缺陷 / 已登记口径差异 / 时间切口差。
- 形式 `it/test_sprint33_reconciliation_scorecard.sh`，沿用 sprint-32 完成门禁脚本风格,作为 Sprint-33 DONE 门禁。

## 影响范围

- 产出记分卡脚本 + 报告模板 + 证据
- 可选健康端点字段 `financeReconciliation`

## 当前进度

- 已落地 `FinanceReconciliationScorecardRegistry`：机器化读取 `finance-reconciliation-scorecard.v1.json`，固化 F1/F2/F3/F4 四条 required lane、0 分容差、以及本地 IT 脚本路径。
- 已落地 `FinanceReconciliationScorecardService`：汇总各 lane 检查项，输出总通过率、分类通过率、失败格数、最大差异、healthStatus、failureMessage。
- 已实现漂移判定：当前失败与 baseline failure 指纹不一致时触发 `DRIFT`；已登记 baseline failure 保持 `FAIL` 但不重复报警。
- 已补强阈值门禁：即使单项检查误报 `passed=true`，只要 `maxDifference > maxAllowedDifference` 仍会失败并触发新漂移。
- 已补强签字基线门禁：`PENDING_SIGNATURE` 的 baseline failure 不会传给 scorecard 当作“已接受差异”，只有财务/审计 `SIGNED` 后才可压制重复漂移告警。
- 已接线 `FinanceReconciliationScorecardSnapshotService`：scorecard 生成后可按权威基准 binding 持久化最新快照，并作为 `FinanceReconciliationScorecardSource` 供财务回答审计包读取；坏 JSON/不可读快照不会伪造健康状态。发布 API/调度结果推荐序列化 `authorityBindingId`，旧 `oracleBindingId` 仅作兼容字段；缺 binding 的错误提示也使用 `authorityBindingId`。
- 已接线 `FinanceReconciliationScorecardPublisherService`：完整 F1/F2/F3/F4 证据包才会发布为最新 scorecard snapshot；缺 required lane 或 lane 只有 `PENDING_LIVE_EVIDENCE` 时只返回待 live 证据且不落库，避免无 live 证据时伪造 PASS/FAIL。
- 已接线 `FinanceReconciliationScorecardScheduledPublisherService`：调度层只消费已注册的 `FinanceReconciliationScorecardEvidenceProvider`，无 provider 时 `SKIPPED`；有 provider 但 publisher 未发布且返回 `PENDING_LIVE_EVIDENCE` 时，顶层同样返回 `PENDING_LIVE_EVIDENCE`，不把 provider-level pending 包装成 `COMPLETED`。
- 已接线 `FinanceReconciliationScorecardResource`：`POST /api/ai/finance/reconciliation-scorecards/publish-scheduled` 可按需触发同一套 scheduled publisher，用于人工复核或上线后调度外补跑。
- 已接线 `FinanceReconciliationScorecardLocalEvidenceProvider`：仅在 `copilot.finance.reconciliation.local-evidence.enabled=true` 时注册，用于本地 readiness 跑通四条 required lane；F3 本地不变量可 PASS，F1/F2/F4 缺 live 数据时显式输出 `PENDING_LIVE_EVIDENCE`，不伪造财务通过。
- 已接线 `FinanceApplicationMysqlAuthorityScorecardCheckService`：F2 应用 MySQL proof runner 结果可转换为 scorecard `f2-summary-voucher` check，checkId 为 `application-mysql-authority-proof`；未配置运行连接时输出 `PENDING_LIVE_EVIDENCE`，proof 差异会保留逐格 cellKey/status/difference；旧 `FinanceApplicationMysqlOracleScorecardCheckService` 仅保留 deprecated 兼容外壳。
- 已接线 `FinanceApplicationMysqlScorecardEvidenceProvider`：仅在 `copilot.finance.reconciliation.application-mysql-evidence.enabled=true` 时注册，把应用 MySQL `proveAll()` 结果作为真实 F2 lane，F1/F4 仍显式 `PENDING_LIVE_EVIDENCE`，F3 使用本地不变量回归，不把应用 MySQL proof 扩大解释成完整 live scorecard。
- 已接线 `FinanceDifferentialGridScorecardEvidenceProvider`：仅在 `copilot.finance.reconciliation.differential-grid-evidence.enabled=true` 且存在 `FinanceDifferentialGridRowProvider` 时注册，把真实 copilot/权威基准网格行转换为 F4 scorecard checks；默认关闭且缺行源不注册，避免伪造 F4 live 通过。
- 已接线 `FinanceDifferentialGridSummarySqlRowProvider`：仅在 `copilot.finance.reconciliation.differential-grid-summary-sql-row-provider.enabled=true` 且存在 copilot/权威基准两个 JDBC query executor 时注册，把已登记 summary SQL 结果映射为差分网格行；支持项目、账期、日期区间切片，未知过滤条件直接失败，避免把未覆盖筛选条件伪造成 live 证据。
- 已接线健康端点字段：`financeReconciliation` HealthIndicator 从 scorecard policy 暴露 `PENDING_LIVE_EVIDENCE`、四条 required lane、IT 脚本路径和 evidence source，不把 live 证据待补误报为 PASS；运行态 `/actuator/health` 已可见 `financeReconciliation=UP`。
- 已新增 `it/test_f4_scorecard_live_preflight.sh` 与 contract：默认只读 `/actuator/health` 并输出 scorecard 前置诊断；只有显式设置 `RUN_LIVE_F4_SCORECARD_PUBLISH=true` 且提供 `FINANCE_RECONCILIATION_SCORECARD_AUTHORIZATION`、`COPILOT_API_KEY` 或 `COPILOT_ADMIN_SECRET` 时才调用 `POST /api/ai/finance/reconciliation-scorecards/publish-scheduled`。使用 `COPILOT_ADMIN_SECRET` 时脚本会创建临时 API key、只输出结构化诊断、不打印原始 key，并在退出时撤销临时 key，避免本地聚合误写 scorecard snapshot 或泄露凭证。
- 2026-06-07 live 预检：重建 `dts-copilot-ai` 后，运行态已加载 `FinanceAuthorityRegistry` 与 `FinanceApplicationMysqlAuthorityRegistry`，`publish-scheduled` 不再 404；`docker-compose.yml` 已显式暴露 `FINANCE_RECONCILIATION_AUTHORITY_*` 并默认启用 honest local readiness provider；使用 `COPILOT_ADMIN_SECRET` 临时 key 执行 live publish 返回 `publish_http_status=200`、`diagnostic.publish_status=PENDING_LIVE_EVIDENCE`、`diagnostic.published_count=0`、`diagnostic.skipped_reason_code=PENDING_LIVE_EVIDENCE`、`reason=scorecard_publish_pending_live_evidence`，原因是 F1 live 权威基准证据仍缺，publisher 未写入 scorecard snapshot。
- 未完成：live F1 端点对账、F4 差分网格真实行源运行参数/数据源配置、真实财务签字 baseline 采信尚未接线；F2 应用 MySQL proof provider 与 F4 差分网格 provider 均已具备 opt-in 接线。
