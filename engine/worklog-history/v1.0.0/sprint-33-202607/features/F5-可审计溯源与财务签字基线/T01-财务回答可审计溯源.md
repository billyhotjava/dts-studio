# T01: 财务回答可审计溯源

**优先级**: P1
**状态**: IN_PROGRESS
**依赖**: F1-F3

## 目标

每个财务回答都能一键展开推导链,让财务/审计能独立复核——把"证明正确"落到"可审计"。

## 技术设计

- 财务回答元数据附:
  1. **执行的精确 SQL**（脱敏后,可复制重跑）。
  2. **应用的口径规则**（命中的 Sprint-31 caliber-rules / F3 不变量,如"用折后实收列""租摆链 a_month_accounting""已排除坏账"）。
  3. **lineage**:结果 → ADS 模型 → 源表/凭证（复用 OpenMetadata/dbt manifest 血缘）。
  4. **oracle 对账状态**:该口径是否在对账集内、最近对账通过/差异。
- 透出位置:agent 回答的"溯源/数据质量"面板（复用现有数据质量提示扩展）,不泄漏敏感连接信息。
- 与 Sprint-32 routeTrace 合并展示（走了哪层 + 口径 + lineage）。

## 影响范围

- `dts-copilot-ai` 回答元数据 + `dts-copilot-webapp` 溯源面板
- 关联 lineage 来源（dbt manifest / OpenMetadata）

## 当前进展

- 已落地 `FinanceAnswerAuditTrailRegistry`：机器化读取 `finance-answer-audit-trail.v1.json`，固化财务回答审计必备区块、oracle binding 到 ADS/规则/不变量/lineage 的映射。
- 已落地 `FinanceAnswerAuditTrailService`：生成脱敏 SQL、Sprint-31 口径规则、F3 不变量、oracle 对账状态、lineage 与 routeTrace 的后端审计包；敏感 JDBC/token/password 片段不会进入可展示 SQL。
- 已落地 `FinanceChatAuditTrailService`：主 chat 计划命中财务报表 code、oracle binding 或 ADS 模型时，自动组装 `trace.financeAudit`；当 `FinanceReconciliationScorecardSource` 返回对应 oracle binding 的最新 scorecard 时，`oracleStatus` 会反映真实 `PASS/DRIFT/FAIL`。
- 已接线 `FinanceReconciliationScorecardSnapshotService`：F4 scorecard 可发布为 oracle binding 最新快照，F5 审计包通过同一 source 读取；source 异常或坏快照只降级为缺失 scorecard，不会吞掉审计包。
- 已接线 `FinanceReconciliationScorecardPublisherService`：F4 完整证据包可发布为 F5 可读取的最新快照；缺 live required lane 时返回 `PENDING_LIVE_EVIDENCE` 且不覆盖已有审计 source。
- 已接入 `AgentExecutionService` / `AgentChatService`：SSE `done` metadata 与持久化 assistant message trace 都会保留 `financeAudit`，供前端面板展开。
- 已扩展 `dts-copilot-webapp` `TracePanel`：当 `trace.financeAudit` 存在时展示财务审计状态、口径规则、不变量和 lineage；SSE done event 与 legacy chat response 兼容解析会保留该字段。
- 当前仍是 IN_PROGRESS：缺少 scorecard source 或 source 无结果时仍明确输出 `MISSING_SCORECARD`，不伪造 PASS；真实 live scorecard 发布运行、财务回答截图/导出和审计复跑待接线。
