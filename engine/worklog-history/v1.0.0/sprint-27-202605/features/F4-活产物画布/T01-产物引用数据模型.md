# T01: 产物引用数据模型与接口

**优先级**: P0
**状态**: DONE
**依赖**: F1(骨架)

## 目标

定义统一的 `Artifact`(活产物)类型与「产物引用」契约——**消息持有产物 id,画布按 id 渲染当前产物**;并提供一个会话级产物存储 hook(`useArtifactStore`),作为画布(F4)与对话(F3/F5)解耦的唯一连接点。本 Task 只定义数据模型、契约与存储,不做渲染(T02)与托盘(T03)。

## 技术设计

### 1. `Artifact` 类型(新建 `src/types/artifact.ts`)

`Artifact` 是画布能渲染的最小自包含单元,产物结构对齐现有 NL2SQL 回答的字段(参考 `copilotGeneratedReportMessage.ts` 的 `inferGeneratedReportSuggestedDisplay` 推断出的 `suggestedDisplay`,以及 `AiAgentChatMessage` 的 `generatedSql` / `targetView` / `dataSurface` / `sourceRefs` 等溯源字段)。

```ts
import type { VisualizationType, VisualizationSettings } from "../components/charts/ChartRenderer";

// 画布数据形状,与 ChartRenderer / DataTable 的入参对齐
export interface ArtifactDataset {
  cols: { name: string; display_name?: string; base_type?: string }[];
  rows: unknown[][];
}

export type ArtifactType = "chart" | "table" | "report";

// 渲染规格:chart/table 用 display+settings+dataset;report 用 reportSpec
export interface ArtifactSpec {
  // chart / table 渲染所需
  display?: VisualizationType;             // 来自 message.suggestedDisplay 推断
  settings?: VisualizationSettings;
  dataset?: ArtifactDataset;
  // report 类(固定报表/报表草稿)渲染所需
  reportCode?: string;                     // 对应 message.reportCode / templateCode
  reportHref?: string;                     // 对应 fixedReport 跳转
  // 溯源/口径(供 T04 动作行与 F6 溯源面板消费,本 Task 只透传)
  generatedSql?: string;
  targetView?: string;
  dataSurface?: string;
  sourceRefs?: string[];
}

export interface Artifact {
  id: string;                  // 产物唯一 id(由生成方分配,见下「id 生成」)
  type: ArtifactType;
  title?: string;              // 托盘/画布标题,默认取问题或报表名
  spec: ArtifactSpec;          // 渲染规格
  sourceMessageId: string;     // 产生该产物的消息 id(反向引用,用于溯源/定位对话)
  createdAt: number;           // 进入托盘排序用
}
```

### 2. 「产物引用」契约

- **消息侧**(F3/F5 持有):`AiAgentChatMessage` 不内嵌产物数据,只携带一个 `artifactId?: string` 引用。本 Task 在 `artifact.ts` 中导出该契约的辅助类型与取值函数,避免改动 `api/types.ts` 的后端契约:

```ts
// 前端会话态对消息的产物引用扩展(不污染后端 AiAgentChatMessage)
export interface MessageArtifactRef {
  messageId: string;
  artifactId: string;
}
```

- **画布侧**(T02 消费):只接收 `Artifact`,不接收 `AiAgentChatMessage`。画布对「当前产物」的唯一输入是一个 `artifactId`,经 `useArtifactStore` 解析为 `Artifact`。

- **id 生成**:`makeArtifactId(sourceMessageId)` 在 `artifact.ts` 内提供,基于 `sourceMessageId` + 自增/`crypto.randomUUID()` 保证同会话内唯一且可追溯到消息。

### 3. 产物存储 hook(新建 `src/hooks/useArtifactStore.ts`)

会话级、内存态(不落库,刷新由 F3 重放消息重建),不可变更新(spread,不就地改 Map):

```ts
export interface ArtifactStore {
  artifacts: Artifact[];                 // 按 createdAt 升序
  currentId: string | null;             // 当前画布产物 id
  current: Artifact | null;             // 派生:currentId 对应的产物
  upsert(artifact: Artifact): void;     // 新 id 新增;同 id 原地更新并保持托盘项数不变
  setCurrent(id: string): void;         // 切换当前产物(托盘点击 / 新产物自动置顶)
  getById(id: string): Artifact | null;
  clear(): void;                        // 切换会话时清空
}

export function useArtifactStore(): ArtifactStore;
```

- 从 `copilotReportDatabase.ts` 借鉴「按 dataSurface/sourceRefs 判定 dbt mart」的纯函数风格:本 Task 把「从一条 NL2SQL 消息构造 Artifact」抽成纯函数 `artifactFromMessage(message, dataset)`(放 `artifact.ts`),供 F5 在出结果时调用,保持画布与消息解耦。
- **原地刷新契约**:不单独暴露 `updateArtifact`。F5 改口径重算、换可视化类型、同一产物内容修订都统一调用 `upsert({ ...artifact, id: existingId, spec: nextSpec })`;store 发现同 `id` 时替换原对象、更新 `current`,但不追加托盘项。
