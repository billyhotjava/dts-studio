# T03: 溯源与纠正契约桩

**优先级**: P0
**状态**: READY
**依赖**: T01

## 目标

为 F6 溯源面板提供结构化 `trace` 契约，并把“口径不对？纠正”收敛为 feedback-first 桩，P2 再接真正评测集/本体草稿写回。

## 技术设计

`trace` 来自 T01 的 `CopilotTrace`，F6 展示优先级：

1. `trace.metricCaliber` / `trace.sources` / `trace.sql`
2. `generatedSql` + `sourceRefs`
3. tool messages 逐步推理记录

纠正接口：

```ts
submitCaliberCorrection({
  sessionId,
  messageId,
  correctionKind,
  metricCaliberRef,
  suggestedCaliber,
  correctedSql,
  reason,
  detail,
})
```

本期实现原则：

- 对外签名稳定，调用方按“纠正口径/表/SQL”提交。
- 内部先落到 `submitChatFeedback`，保留 `correctionKind`、`metricCaliberRef`、`correctedSql` 等上下文。
- 不真正写回评测集/本体草稿；代码注释标明 `TODO(P2/sprint-26 adminapi)`。

## 影响范围

- `dts-copilot-webapp/src/api/modules/copilot.ts`
- `dts-copilot-webapp/src/api/analyticsApi.ts`
- F6 `TracePanel` / `FeedbackButtons`
- `dts-copilot-ai` / `dts-copilot-analytics` feedback endpoint 可选上下文

## 验证

- [ ] `trace` 存在时溯源面板展示口径、表字段、SQL。
- [ ] `trace` 缺失时回退到 `generatedSql` / `sourceRefs` / tool messages。
- [ ] 纠正提交调用 `submitCaliberCorrection`，payload 含 `correctionKind` / `messageId` / `sessionId`。
- [ ] 本期不会调用真实本体草稿写回端点。

## 完成标准

- [ ] F6 的结构化溯源和纠正入口有统一契约。
- [ ] 纠正数据不会丢，但不会误承诺“已学习”。
- [ ] P2 可直接替换桩实现，不需要改 F6 UI 调用方。
