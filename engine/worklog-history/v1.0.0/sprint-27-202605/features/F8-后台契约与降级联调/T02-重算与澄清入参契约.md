# T02: 重算与澄清入参契约

**优先级**: P0
**状态**: READY
**依赖**: T01

## 目标

为“改口径重算”和“低置信澄清后继续执行”定义统一请求契约，确保同步发送和 SSE 发送走同一条 body 结构。

## 技术设计

`aiAgentChatSend` 与 `aiAgentChatSendStream` 的 body 扩展：

```ts
{
  sessionId?: string;
  userMessage: string;
  datasourceId?: string;
  assumptionOverrides?: Record<string, string>;
  clarificationAnswers?: Record<string, string>;
}
```

语义：

- `assumptionOverrides`：用户修改常驻口径芯片后，按 key 锁定新的口径值再生成 SQL。
- `clarificationAnswers`：低置信反问时，用户选择澄清项后带答案继续执行。
- 两者均为可选；后台未支持时不得导致 4xx，前端将以降级说明处理，但不能把 IT05/IT06 标记为真实契约通过。

## 影响范围

- `dts-copilot-webapp/src/api/modules/copilot.ts`
- F3 `useCopilotStream` / 发送 body 构造
- F5 `handleRecompute` / `ClarificationChips.onAnswer`
- `dts-copilot-ai` Agent chat request DTO
- `dts-copilot-analytics` session proxy 转发

## 验证

- [ ] 改口径时请求体包含 `assumptionOverrides`。
- [ ] 澄清后继续执行时请求体包含 `clarificationAnswers`。
- [ ] SSE 与同步 fallback 两条路径 body 一致。
- [ ] 后台返回新 `assumptions` 时覆盖旧芯片值；后台忽略 override 时前端给出可诊断降级证据。

## 完成标准

- [ ] 入参契约在前端 API、SSE、后台 DTO、proxy 转发中一致。
- [ ] F5 的“改芯片重算”和“低置信反问”不再依赖隐式字符串拼接。
- [ ] IT05/IT06 有 mock 契约和真实契约两类证据位。
