# T02: 定义新工作台路由与首页壳

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标

新建 agent 工作台页面与路由，把它确立为系统唯一入口（spec §4「唯一入口 = 一个 agent 工作台」）。本 Task 只搭「路由 + 页面壳占位」骨架，真实的冷启动首屏（F2）、对话脊柱（F3）、活产物画布（F4）由各自 Feature 填充进本壳预留的插槽。

## 技术设计

1. **新建工作台页面壳**（`dts-copilot-webapp/src/pages/`）：
   - 新建 `AgentWorkspacePage.tsx`，`export default`，作为工作台容器组件。
   - 内部按 spec §4「状态二」预留三个区域占位：左导航（由 T04/SidebarNav 提供）、中部对话脊柱插槽（F3）、右侧活产物画布插槽（F4）。本 Task 用占位元素（如「对话区占位 / 画布区占位」）填充，不实现业务逻辑。
   - 「冷启动首屏 vs 进入分析」两态由 F2 决定，本 Task 只渲染一个最简空态壳，确保路由可达、构建通过。
   - 命名遵循 PascalCase；props 用具名 `interface`；不使用 `React.FC`。

2. **路由注册**（`dts-copilot-webapp/src/routes.tsx`）：
   - 在 `AppLayout` 的 `children` 中新增 `/agent-bi`（T01 已删除旧注册）指向 `lazyComponent(() => import("./pages/AgentWorkspacePage"))`。沿用 `APP_HOME_PATH` 以最小化对外部书签/平台跳转的破坏。
   - 根路径 `/`（行 46 `ModernAliasRedirect`）与 `APP_HOME_ALIASES`（`/home`、`/modern`）继续重定向到 `APP_HOME_PATH`；确认 `ModernAliasRedirect` 在 T01 后仍指向新工作台。
   - `*` 兜底仍为 `NotFoundPage`。

3. **首页常量**（`dts-copilot-webapp/src/appShellConfig.ts`）：
   - `APP_HOME_PATH` 维持 `'/agent-bi'`（语义已从「旧报表页」变为「工作台」）。若按 spec §4 倾向用 `/` 作为工作台根，可在此 Task 评估改为 `/`：改则同步 `routes.tsx` 根路由由「重定向」变为「直挂工作台」、并更新 `APP_HOME_ALIASES` / `CORE_NAV_PATHS`。**默认保守方案**：保留 `/agent-bi`，仅语义重定义，降低 F4 之前的迁移风险。
   - `CORE_NAV_PATHS`（`[APP_HOME_PATH, '/dashboards']`）按 T04 导航收口结果同步调整。

4. **CopilotSidebar 浮窗处置**：`AppLayout` 当前在 `location.pathname === "/agent-bi"` 时内嵌而非浮动（`copilotEmbeddedInPage`）。新工作台壳保持「内嵌」语义；浮动 `CopilotSidebar` 的去留在 T03 双栏壳改造时统一处理，本 Task 不重复实现聊天。

## 影响范围

（真实文件/模块/路由/接口）

- 新建：`src/pages/AgentWorkspacePage.tsx`（可附 `AgentWorkspacePage.css` 占位样式）

- 协作插槽：F2 冷启动首屏、F3 对话脊柱、F4 活产物画布（本 Task 仅留占位）
