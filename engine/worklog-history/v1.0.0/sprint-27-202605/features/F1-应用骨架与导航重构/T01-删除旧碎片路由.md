# T01: 删除旧 NL2SQL/报表碎片路由与页面

**优先级**: P0
**状态**: DONE
**依赖**: F3-T00 现状测试基线

## 目标

按设计决策 D7「直接删除、彻底重构，不背兼容包袱」，移除入口碎片化的旧 NL2SQL / 报表页面及其路由注册和过渡跳转，为 T02 的新工作台让出 `/agent-bi`（及 `/`）入口。本 Task 只做「删除与清理」，不新增任何页面（新工作台壳由 T02 负责）。执行前必须先完成 F3-T00,避免在无测试基线时删除现有聊天入口。

被删页面对应 spec §1 诊断的「6+ 个互不相通的路由孤岛」：`/analyze`、`/explore-sessions`、`/report-factory`、`/metric-lens`，以及将被新工作台取代的旧 `AgentReportsPage`（`/agent-bi`）。

## 技术设计

1. **删除页面文件**（`dts-copilot-webapp/src/pages/`）：
   - `AnalyzePage.tsx`
   - `ExploreSessionsPage.tsx`
   - `ReportFactoryPage.tsx`
   - `MetricLensPage.tsx`
   - `AgentReportsPage.tsx` + 配套 `AgentReportsPage.css`、`AgentReportsPage.test.tsx`（旧工作台，将由 T02 新页面取代）
   - 评估并一并清理仅服务于上述页面的支撑模块：`analysisAssetProvenanceEntry.ts`、`analysisDraftReuseModel.ts`、`analysisDraftSurfaceEntry.ts`、`analysisProvenanceModel.ts`、`queryAssetCenterModel.ts`（先用 `grep -rn` 确认无其他保留页面引用，再删；被资产库/溯源 Feature 复用的不删，转交对应 Feature）。

2. **清理 `routes.tsx` 路由注册**（`dts-copilot-webapp/src/routes.tsx`）：
   - 删除 `/agent-bi`（旧 `AgentReportsPage` 注册，行 49）—— 由 T02 重新指向新工作台。
   - 删除 `/analyze`（行 50）、`/explore-sessions`（行 78）、`/report-factory`（行 79）、`/metric-lens`（行 82）的 `lazyComponent` 注册。
   - 删除过渡跳转组件与注册：`ScreensCenterRedirect`（行 14-16，注册于行 77 `/screens`）、`FixedReportsRedirect`（行 18-24，注册于行 80-81 `/fixed-reports`、`/fixed-reports/:templateCode/run`）。`/screens` 路由删除后由 `screens/ScreensPage` 或资产库接管（属 F7 范围，本 Task 仅移除重定向桩）。
   - `ModernAliasRedirect`（行 6-12）暂保留，其目标 `APP_HOME_PATH` 在 T02 切换；本 Task 不改其逻辑。

3. **必须保留（不可误删）**：
   - `/public/card/:uuid`（行 75）、`/public/dashboard/:uuid`（行 76）、`/public/screen/:uuid`（行 42）—— 决策 D10 外发分享链接。隔离验证见 T05。
   - `dashboards` / `questions`（`CardsPage` 等）/ `collections` / `screens` 页面与路由 —— 降级供 F7 资产库复用。
   - `data` / `models` / `metrics` / `admin/*` 路由 —— 保留作治理后台。
   - `/search`（`SearchPage`）暂保留，归属由后续 Feature 决定，本 Task 不动。

4. **i18n 与引用清理**：删除页面后全仓 `grep` 残留 import / 路由常量 / i18n key（如 `nav.analyze`、`nav.exploreSessions` 等），逐一清除死引用，避免 `tsc` 残留报错。
