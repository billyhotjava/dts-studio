# T03: 低置信降级反问(澄清芯片单选)

**优先级**: P0
**状态**: READY
**依赖**: T02(乐观执行流 + 置信度判定)、F8-T01(clarifications 响应契约)、F8-T02(clarificationAnswers 入参契约)

## 目标

实现 agent 性格的另一面(D4):当本体匹配置信度低到大概率猜错时,**不直接出结果**,而是降级为反问——在结果卡渲染一组「澄清芯片」(单选,如「本月 = 自然月 | 账期」),用户选定后再带选择**继续执行**。这是乐观执行的安全阀:多数走 T02 直接出结果,少数高歧义时先问一句避免给错答案。

> 设计依据:spec D4「仅当置信度低到大概率猜错时降级为反问」。

## 技术设计

### 降级判定与阈值

- 复用 T02 的 `OPTIMISTIC_CONFIDENCE_THRESHOLD`(`assumptionConfidence.ts`),`shouldExecuteOptimistically(confidence) === false` 即进入降级反问路径。阈值语义写清:
  - `confidence >= 0.6` → 乐观直接执行(T02)。
  - `confidence < 0.6` 且后台给出 `clarifications[]` → 渲染澄清芯片,先问后执行(本 Task)。
  - `confidence < 0.6` 但后台**未**给 `clarifications[]` → 回退到「仍乐观出结果 + 假设芯片可改」(降级不可用时不卡死用户,改口径走 T04 兜底)。
- 阈值作为单一常量集中管理(可后续配置化),避免散落魔法数。

### 接口契约扩展(澄清项)

- `src/api/types.ts`:
  ```ts
  export interface CopilotClarification {
    key: string;          // 对应歧义维度,如 "period"
    question: string;     // 反问文案,如 "本月按哪种口径?"
    options: { value: string; label: string }[]; // 单选项,如 自然月 / 账期
  }
  ```
  - `AiAgentChatMessage` 增 `clarifications?: CopilotClarification[]`。
  - `CopilotStreamEvent.done` 增 `clarifications?: CopilotClarification[]`;`copilotApi.aiAgentChatSend` 同步响应同步透传。
- `CopilotSendBody` 入参增 `clarificationAnswers?: Record<string, string>`(key → 选定 value),供「答完反问再发起」携带。
- **后台待办(F8-T01/T02)**:低置信时 NL2SQL agent 输出 `clarifications[]` 而非直接结果;收到带 `clarificationAnswers` 的请求时按答案锁定口径再执行。前端先按契约做,后台未支持前该路径不可达(因后台不会返回 `clarifications`),不影响 T02 主路径。

### 渲染与交互

- 新建 `src/components/copilot/assumptions/ClarificationChips.tsx`:
  - Props:`{ clarifications: CopilotClarification[]; onAnswer: (answers: Record<string, string>) => void; disabled?: boolean }`。
  - 每个 clarification 渲染反问文案 + 一组单选芯片(`role="radio"` / `radiogroup`,键盘可达);多个维度时各自单选。
  - 全部必填维度选定后启用「继续」按钮 → 调 `onAnswer(answers)`。
- 结果卡渲染分流(`CopilotChat.tsx` / F3 消息渲染单元):
  - 该消息有 `clarifications?.length` 且非乐观执行 → 渲染 `ClarificationChips`,**隐藏** SQL 预览/产物(还没真正执行)。
  - `onAnswer` → 以原问题 + `clarificationAnswers` 重新发起 `handleSendText`(走 T04 的重发起通道:复用产物 id,见 T04;此处首问尚无产物,直接新发起即可)。
- 状态收尾:答完反问发起执行后,该「反问态」消息或被新结果替换,或标记 `clarificationAnswered` 不再可点(防重复提交)。
