# T04: 芯片可改 → 重算 → 画布原地刷新

**优先级**: P0
**状态**: DONE
**依赖**: T01(口径芯片 `onCommit`)、T02(发送流)、F4(活产物画布 + `useArtifactStore`)、F8-T02(assumptionOverrides 入参契约)

## 目标

打通「改假设 → 重算 → 产物刷新」闭环:用户点 T01 的口径芯片改假设(如把「本月=2026-05」改成「2026-04」)→ 以**新假设**重新发起查询(带 `assumptionOverrides`)→ F4 活产物画布对应产物**原地刷新**(复用同一 `artifactId` 更新内容,**不新增产物**,旧产物不进托盘)。这是乐观执行「先出结果、再让用户微调口径」体验的关键收尾。

> 设计依据:spec D4(把假设做成可点改芯片)、D6(默认当前产物,不平铺)、§8 模块边界「消息持有产物 id,画布按 id 渲染当前产物」。

## 技术设计

### 重算入参契约

- `CopilotSendBody`(由 `analyticsApi.aiAgentChatSend` 入参推导)增 `assumptionOverrides?: Record<string, string>`(key → 用户改后的 value),`aiAgentChatSendStream` 的 body 同步支持(`src/api/modules/copilot.ts`)。
- **后台契约(F8-T02)**:收到带 `assumptionOverrides` 的请求时,AI 侧把 override 写入 prompt,生成 SQL/执行时优先遵守,并在 `done` 返回更新后的 `assumptions[]`(以 `sourceHint=user_override` 回显改后值)。前端已能发起重算请求并刷新画布(以新 SQL 结果为准);T04 live 验收仍以真实部署链路验证为完成前提。

### 重发起 + 产物 id 复用

- 在 `ConversationThread.tsx` / `useCopilotStream.ts`(F3 发送单元)新增重算路径:
  - 取该 assistant 消息对应的**用户原问题**(`getUserQuestionForAssistant`,已存在于 `CopilotChat.helpers`)。
  - 构造 `body: CopilotSendBody = { userMessage: 原问题, sessionId, datasourceId, assumptionOverrides: overrides }`。
  - 复用现有发送通道(`aiAgentChatSendStream` + 同步回退),但通过 `replaceAssistantMessageId` 更新原 assistant 消息,并把待刷新的 `artifactId` 透传进流式处理闭包。
- **画布原地刷新(对接 F4 `useArtifactStore`)**:
  - F4 约定 `Artifact { id, type, spec, sourceMessageId }`,画布按 `id` 渲染当前产物。
  - 重算的 `done` 事件到达后,**不**调用「新增产物」,而是调用 F4 `useArtifactStore.upsert({ ...artifact, id: artifactId, spec: nextSpec })`。F4 规定同 `id` `upsert` 为原地更新,使画布刷新、托盘不新增条目。
  - 若按 `sourceMessageId` 重建产物,也必须生成同一 `artifactId`;不得因为重算产生新托盘项。
  - `InlineSqlPreview` 侧:重算后 `committedSql` 随新 SQL 更新触发其既有 `autoRun` 重新预览(组件已支持 `sql` 变化时重置并自动跑,见 `InlineSqlPreview` `useEffect([sql])` + `autoRun` 逻辑),结果卡内表格同步刷新。
- **芯片回调接线**:T01 的 `EditableAssumptionChips.onCommit(key, nextValue)` → 在消息渲染单元聚合成 `overrides`(可一次改一项即重算,或允许累积多项后统一重算;P1 取「改一项即重算」最简路径)→ 调 `handleRecompute`。重算进行中给芯片 `disabled`(T01 已支持)防重复触发。

### 防回归要点

- 重算**不得**新增产物 / 不得在托盘里多出一条(D6);通过「复用 artifactId 更新」而非「push 新产物」保证。
- 重算复用 F3 既有流式/超时/停止/同步回退机制,不另起一套发送逻辑(DRY)。
- 改后回显:`done` 返回的新 `assumptions[]` 覆盖消息上的旧值,芯片显示更新后取值。

## 影响范围

- 修改:`src/api/modules/copilot.ts` —— `aiAgentChatSend` 入参 + `aiAgentChatSendStream` body 增 `assumptionOverrides`(`CopilotSendBody` 随之扩展)。
- 修改:`ConversationThread.tsx` / `useCopilotStream.ts` / F3 发送单元 —— 新增重算路径,接 T01 芯片 `onCommit`,透传待刷新 `artifactId`。
- 修改:`AgentWorkspacePage.tsx` —— 工作台挂接 `ConversationThread + CanvasPanel + useArtifactStore`,使对话与画布共享产物 store。
- 对接:F4 `src/types/artifact.ts` + `useArtifactStore.upsert`(同 id 原地刷新);集成时与 F4 T01 接口对齐。
- 复用:`getUserQuestionForAssistant`(`CopilotChat.helpers`)、`InlineSqlPreview`(SQL 变化自动重预览)、F3 流式发送通道。
- 后台契约:F8-T02 支持 `assumptionOverrides` 锁口径重算并回显新 `assumptions`。
