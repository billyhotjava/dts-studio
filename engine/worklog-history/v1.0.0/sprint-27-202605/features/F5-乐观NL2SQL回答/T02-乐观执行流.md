# T02: 乐观执行流(高置信直接出结果 + 假设芯片)

**优先级**: P0
**状态**: DONE
**依赖**: T01(口径芯片组件)、F3(对话脊柱发送/流式接入)、F8-T01(聊天响应契约)

## 目标

实现 agent 的「乐观执行」主路径(D4):高置信度时,一句话问数**直接流式出结果**,同时把后台返回的关键假设 `assumptions[]` 落到消息上,由 T01 的 `EditableAssumptionChips` 常驻渲染。本 Task 负责**消费后台返回的口径/假设/置信度字段并扩展接口契约**;低置信降级反问由 T03 接手,改后重算由 T04 接手。

> 设计依据:spec D4(按本体置信度直接出结果,把假设做成可点改芯片)、§6 回路「⚡ 乐观出结果 + 假设芯片」、§8 复用 `aiAgentChatSendStream` / `analyticsApi`。

## 技术设计

### 接口契约扩展(关键:后台当前未返回这些字段)

落地结论:`AiAgentChatMessage`、`AiAgentChatResponse`、`CopilotStreamEvent.done`(`src/api/types.ts`)已携带 assumptions / confidence;SSE done 与 legacy 同步归一化均做容错透传。前后端真实输出仍归 F8-T01 补齐;F5 消费方式为前端先落类型并做容错(有则用、无则不显示芯片,退回现有 `qualityNotes`/`responseKind` 行为)。

- `src/api/types.ts`:
  - `AiAgentChatMessage` 增 `assumptions?: CopilotAssumption[]`(T01 已加)、`confidence?: number`(0–1)。
  - `CopilotStreamEvent` 的 `done` 分支增 `assumptions?: CopilotAssumption[]`、`confidence?: number`。
- `src/api/modules/copilot.ts`:
  - `aiAgentChatSendStream` 的 `done` 解析透传 `parsed.assumptions` / `parsed.confidence`,并保留 `confidence=0` 这类低置信有效值。
  - 同步回退响应同样在归一化层(`normalizeLegacyAiChatResponse` / 平台响应)透传这两字段(若缺则为 undefined)。
- **后台契约(F8-T01)**:NL2SQL agent 已在 `done`/同步响应中输出 `assumptions[]`(每条 `{ key, label, value, editable?, options?, sourceHint? }`,基于规划口径与用户确认输入生成)与 `confidence`(0–1,本体匹配置信度)。字段缺失时,前端高置信路径表现为「出结果但无芯片」,功能可用、不报错。

### 乐观执行渲染流

- 在 `src/components/copilot/useCopilotStream.ts` 的 `done` 事件处理中,通过 `reduceCopilotStreamMessages` 把 `event.assumptions` / `event.confidence` 一并合并进 assistant 消息。
- **置信度判定**(新建纯函数,放 `src/components/copilot/assumptions/assumptionConfidence.ts`):
  ```ts
  export const OPTIMISTIC_CONFIDENCE_THRESHOLD = 0.6; // 可配,见 T03
  export function shouldExecuteOptimistically(confidence: number | undefined): boolean {
    // 缺失置信度时默认乐观执行(向后兼容后台未返回的情况)
    return confidence == null || confidence >= OPTIMISTIC_CONFIDENCE_THRESHOLD;
  }
  ```
  本 Task 实现并默认走「乐观执行」;`shouldExecuteOptimistically === false` 的分支(降级)在 T03 完整落地,本 Task 仅预留判定点与阈值常量(供 T03 复用,DRY)。
- 结果卡:高置信且 `msg.assumptions?.length` → 渲染 T01 芯片;`assumptions` 为空仍正常出结果(纯文本/SQL/表格),不强行造芯片。
