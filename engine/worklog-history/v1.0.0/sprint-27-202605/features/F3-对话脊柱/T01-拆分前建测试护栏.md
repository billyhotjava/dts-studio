# T01: 拆分前先建测试护栏

**优先级**: P0
**状态**: READY
**依赖**: T00

## 目标

在 T00 已建立现状基线的前提下,补齐更细的 vitest 护栏,把现有关键行为固化为可执行断言(消息渲染、`handleSendText` 发送、SSE 流式状态、停止),建立「行为不变」的重构基线 —— 拆分前后跑同一套测试必须全绿,任何回归立即暴露。

## 技术设计

护栏分两层,均落在 `src/components/copilot/` 下,跑 `pnpm test`(vitest)。

### 1. 行为单元护栏(纯逻辑,不依赖渲染)

现有可拆出的纯逻辑已大部分有测试(`copilotStreamControl.test.ts`、`copilotReasoningState.test.ts`、`copilotComposerState.test.ts`、`copilotInputBehavior.test.ts`、`copilotSessionBootstrap.test.ts`、`copilotSessionFocus.test.ts`)。本任务先**核对覆盖完整性**并补齐 4 类发送/流式相关断言:

- 发送守卫:`handleSendText` 的前置条件(`!copilotEnabled` → 报 `copilotDisabledMessage`;空串 / `sending` / `streamInFlightRef` 在飞行中时 no-op)。把这段判断抽成可测纯函数(如 `resolveSendGuard`)放入 `CopilotChat.helpers.ts` 或新建 `copilotSendGuard.ts`,补 `*.test.ts`。
- 流式事件归并:对 `aiAgentChatSendStream` 的回调,用 `session/reasoning/token/tool/done/error` 事件序列驱动一个纯 reducer(把 `setMessages(prev => ...)` 内联逻辑抽成 `reduceCopilotStreamEvent(messages, event, ctx)`),断言:`token` 累加进 `content`、`reasoning` 累加进 `reasoningContent` 且首个 reasoning 清掉 `STREAM_PENDING_REASONING`、`done` 写入 `generatedSql`/`responseKind` 等字段、`error` 写入 error 文案。
- 停止:`abortStreaming` / `handleStopStreaming` 的语义(有 abortController 时 abort 并返回 true、可带 notice;无时返回 false),用现有 `copilotStreamControl` 的 `resolveCopilotSendAction`(`stop` / `interrupt-and-send` / `send`)断言「停止 vs 打断重发」的分支选择。

### 2. 结构护栏(源码字符串断言,锁渲染契约)

沿用并扩展现有 `CopilotChat.presentation.test.ts` 的 `readFileSync` 模式。该文件当前断言源码含 `compactReasoning`、`copilot-chat__reasoning-details`、`<CopilotMessageContent content={msg.content} />`,且**不含** `copilot-chat__assistant-echo` / `Agent 回显`。本任务:

- 在拆分前先扩充该护栏,新增断言锁住「消息流渲染契约」「输入区契约」的关键 DOM 标记(如 `copilot-chat__messages`、`VoiceInputButton`、发送按钮 `sendAction.label`、`InlineSqlPreview`、`TracePanel`、`FeedbackButtons` 的挂载点),作为拆分时的「不许丢」清单。
- 明确记录:T02 拆分后这些字符串会迁移到子组件文件,届时断言需 `readFileSync` 对应子组件文件(`MessageList.tsx` / `Composer.tsx`)而非主文件 —— 在测试里用注释标注迁移目标,降低 T02 改测试的认知成本。

> 说明:本仓库 vitest 环境对完整 `CopilotChat` 的 DOM 渲染测试成本高(强依赖 `analyticsApi` / SSE / sessionStorage)。护栏优先走「纯逻辑 reducer + 源码结构断言」组合,避免引入脆弱的全组件挂载测试;真正的端到端交互留给后续 e2e。

## 影响范围
