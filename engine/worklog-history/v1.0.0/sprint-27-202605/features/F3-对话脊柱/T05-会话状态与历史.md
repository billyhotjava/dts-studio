# T05: 会话状态与历史

**优先级**: P0
**状态**: DONE
**依赖**: T02

## 目标

把会话生命周期(bootstrap 恢复 / focus 回跳 / 列表加载 / 新建 / 切换 / 删除 / 消息恢复 / 数据源持久化)收口到 `useCopilotSessionState` hook,并把「💬历史会话」列表数据接入 `copilotApi.listAiAgentSessions`(经 `analyticsApi` 聚合),支持在脊柱内新建、切换、恢复会话,行为与拆分前一致。

## 技术设计

### `useCopilotSessionState.ts`(迁自 `CopilotChat.tsx` 的会话相关 state + effect)

承接的状态:`sessionId` / `sessions` / `messages` / `pendingAction` / `databases` / `selectedDbId` / `focusNotice` / `focusedMessageId` / `initialStoredSessionId` ref。承接的逻辑:

- **列表加载** `reloadSessions`:`copilotEnabled` 为假返回 `[]`;否则 `analyticsApi.listAiAgentSessions(50)` → `toArray<AiAgentChatSession>` → 按 `lastActiveAt` / `createdAt` 倒序排序 → `setSessions`。失败 best-effort 返回 `[]`。
- **消息恢复** `reloadMessages(sid)`:`getAiAgentSession(sid)` → `sortMessages` → best-effort `listAnalysisDrafts` + `attachAnalysisDraftLinksToMessages` → `setMessages` + `setPendingAction(detail.pendingAction)`。
- **sessionId 持久化** effect:写/删 `SESSION_ID_KEY`(`sessionStorage`)。
- **数据源加载 + 持久化**:挂载时 `analyticsApi.listDatabases` → `setDatabases`,默认选中存储值或首个;`selectedDbId` 变化写 `DATASOURCE_ID_KEY`。
- **bootstrap** effect:`reloadSessions` 后用 `initialStoredSessionId` + `shouldRestorePersistedCopilotSession`(`copilotSessionBootstrap`)决定是否保留持久化会话;若当前会话已不在列表中则置空 `sessionId`。恢复判断只基于初始存储 session,不会覆盖「新对话」态。
- **消息恢复** effect:`sessionId` 变化时 `reloadMessages`,但 `streamInFlightRef.current && activeStreamingSessionIdRef.current === sessionId` 时跳过(防止流式进行中抢答)—— 该 ref 来自 T03 的 `useCopilotStream`,经容器在两 hook 间共享。
- **focus** effect:`focusRequest?.sessionId` 变化时 `setSessionId` + `setFocusNotice` + `setFocusedMessageId` + `reloadMessages`(`copilotSessionFocus`,来源对话回跳;由 `CopilotSidebar` 监听 `COPILOT_SESSION_FOCUS_EVENT` 注入)。
- **滚动 / 高亮** effect:内容更新滚到底;`focusedMessageId` 变化时 `scrollIntoView` 到 `[data-copilot-message-id]`。

### 会话动作(供 `Composer` 会话条与新对话按钮调用)

- `handleNewChat`:清 `queuedInput` / `sessionId` / `messages` / `pendingAction` / `error` / `focusNotice` / `focusedMessageId` / `approvalValues`(置空新对话态)。
- `handleDeleteSession`:`deleteAiAgentSession(sessionId)` → `reloadSessions` → 选下一个会话或清空。
- 会话切换:`select` onChange,空值走 `handleNewChat`,否则清 focus + `setSessionId`。

### 「💬历史会话」列表接入

- spec §4 状态二左导航的「💬历史会话」入口由 **F1** 提供承载位;**本任务负责其数据来源**:复用 `useCopilotSessionState` 的 `sessions`(`listAiAgentSessions` 返回 `AiAgentChatSession[]`,含 `id` / `title` / `lastActiveAt`)。
- 历史会话项点击 → 走会话切换路径(`setSessionId` + `reloadMessages`),与 `Composer` 会话条下拉同源;若 F1 的历史会话面板是独立组件,则通过容器把 `sessions` / `onSelectSession` / `onDeleteSession` 暴露出去复用,避免两份会话状态。
- 列表排序按 `lastActiveAt` 倒序(若后端未保证有序,在前端按 `lastActiveAt` 排序后展示)。

### `promptRequest` prefill 衔接(保留)

容器层保留 `resolveCopilotPromptHandoff`(`copilotPromptHandoff`)对 `promptRequest` 的消费(`submit` / `queue` / prefill 三模式),`submit` 落 `handleSendText`(T03),prefill 设 `input` + focus `inputRef`。该链路由 `AiAssistantFab` 监听 `dts:ai-quick-ask` → 转 `COPILOT_PROMPT_REQUEST_EVENT` → `CopilotSidebar` 注入 `promptRequest`,F3 拆分须保持不变。
