# T03: 纠正入口（占位 + 回流接口预留）

**优先级**: P1
**状态**: DONE
**依赖**: T01（面板形态）、T02（口径展示，纠正对象即命中口径）、F8-T03；复用 `FeedbackButtons`

## 目标

在溯源面板口径分区旁提供「⚑口径不对？纠正」入口，复用 `FeedbackButtons` 采集用户的纠正意见（针对命中口径/表/SQL）。本期**只做 UI + 反馈采集**：纠正提交走 F8-T03 定义的 feedback-first 桩并带上「纠正语义」上下文；**回流到 NL2SQL 评测集 / 本体草稿（对接 sprint-26 adminapi 写回）只留接口桩**，P2 实现完整回流（spec 第二里程碑「纠正即学习」）。

## 技术设计

### 现状（已核对源码）

- `src/components/copilot/FeedbackButtons.tsx`：👍/👎 + 负反馈表单（理由芯片 `NEGATIVE_REASONS` 含「SQL不正确/数据不准确/查错了表/没理解我的意思/…」+ 补充说明），提交走 `analyticsApi.submitChatFeedback`。Props：`messageId/sessionId/generatedSql/routedDomain/targetView/templateCode`。
- `src/api/modules/copilot.ts` `submitChatFeedback`（L212-229）：已支持 `rating/reason/detail/generatedSql/correctedSql/...`，POST `/api/ai/nl2sql/feedback`。**已含 `correctedSql` 字段**，可作为纠正回流的最小载体。
- `FeedbackButtons.test.tsx`：覆盖渲染、点赞激活、点踩表单、取消恢复。

### 实现

1. **纠正入口（占位 UI）**：在 `TracePanel.tsx` 口径分区（T02）旁加「⚑口径不对？纠正」按钮。点击展开「纠正面板」：
   - 复用 `FeedbackButtons` 的负反馈采集能力。两种落地方式（择一，倾向 b 以保持单一反馈出口）：
     - a) 直接复用 `FeedbackButtons`，新增可选 prop `variant?: "inline" | "correction"` 与 `defaultReason?`（默认选中「SQL不正确」/「查错了表」），开放为纠正态；
     - b) 在面板内调用 `FeedbackButtons` 的受控负反馈表单（抽出 `NegativeFeedbackForm` 子组件复用），避免在结果卡和溯源面板出现两套交互。
   - 采集内容：纠正理由（芯片）+ 文字说明；可选「期望口径/期望 SQL」输入（映射到 `correctedSql` 与新增上下文字段）。
2. **携带纠正上下文**：提交时在 `submitChatFeedback` 载荷上补纠正语义（最小改动，复用现有接口）：
   - `rating: "negative"`、`reason`、`detail`、`generatedSql`、`correctedSql`（已存在）；
   - 新增可选上下文：`correctionKind?: "metric_caliber" | "table" | "sql"`、`metricCaliberRef?`（来自 T02 `trace.metricCaliber.ontologyRef`）、`routedDomain`。这些字段后台暂可忽略，仅采集留痕。
3. **回流接口桩（F8-T03 / P2 占位）**：在 `copilot.ts` 新增**桩函数**，签名与 sprint-26 adminapi 写回对齐，但本期不真正写回：
   ```ts
   // P2 实现：回流到 NL2SQL 评测集 / 本体草稿（对接 sprint-26 adminapi 写回）
   submitCaliberCorrection: (body: {
     sessionId: string;
     messageId: string;
     correctionKind: "metric_caliber" | "table" | "sql";
     metricCaliberRef?: string;   // 本体口径节点引用
     suggestedCaliber?: string;   // 用户建议口径/公式
     correctedSql?: string;
     reason?: string;
     detail?: string;
   }) => {
     // STUB(P2/sprint-26): 暂不写回评测集/本体草稿。
     // 本期仅复用 submitChatFeedback 采集，确保用户反馈不丢。
     // P2 接 adminapi：POST /api/admin/ontology/caliber-drafts 或 /api/ai/nl2sql/eval/cases
     return Promise.resolve({ accepted: true, queued: false as const });
   }
   ```
   - 桩内部本期落到 `submitChatFeedback`（保证采集不丢）；对外签名稳定，P2 仅替换实现为真正写回，调用方无需改动。
   - 在桩函数与调用处加 `// TODO(P2/sprint-26 adminapi)` 注释，并在 `worklog` 标注 P2 衔接。
4. **状态反馈**：提交成功复用 `FeedbackButtons` 的「感谢反馈」态；失败复用其错误提示。
5. **不做**：真正写入评测集 / 本体草稿、本体地图跳转纠正、审核流——均 P2。
