# T03: 资产库二级入口

**优先级**: P1
**状态**: READY
**依赖**: F1(已保留 `CardsPage` / `DashboardsPage` / `CollectionsPage` 等页面组件)

## 目标

按决策 **D5**(spec §3)与 **§5-B**,把旧 BI 的看板/卡片/集合浏览能力收拢成一个 **「📁资产库」二级入口**(左导航一级图标之一,但页面内是聚合的二级浏览页,不再是三个并列一级菜单)。在一个 `AssetLibraryPage` 内用 **Tab / 分组** 呈现「看板 / 卡片 / 集合」三类资产,直接复用现有页面组件的浏览能力,避免重写列表逻辑。

## 技术设计

### 入口与路由

- 左导航一级图标 `📁资产库`(spec §4 状态二的 4 个一级入口之一)指向 `/assets`(具体路由由 F1/导航 Feature 落,本 Task 提供页面)。
- `/assets` 渲染 `AssetLibraryPage`,内部 Tab 切换;Tab 状态写进 URL(`?tab=dashboards|cards|collections`,遵循「URL as state」),保证可分享/可刷新保持。

### 复用策略(关键:不重写列表)

现有三个页面组件均为默认导出的完整页(各自含 `PageContainer` + 拉数 + 列表),可直接作为 Tab 内容嵌入:

- `pages/DashboardsPage.tsx`(`listDashboards` + 固定报表快捷区)
- `pages/CardsPage.tsx`(基于 `queryAssetCenterModel` 的 cards+drafts 归一化浏览)
- `pages/CollectionsPage.tsx`(`listCollections`)

实现优先级:
1. **首选**:`AssetLibraryPage` 仅作壳 —— 提供顶部统一标题 + Tab,Tab 内容直接挂载现有页面组件。最小改动、零重写。
2. 若现有页各自的 `PageHeader` 在嵌入后视觉重复,抽出「列表主体」子组件(把 `PageHeader` 留在 `AssetLibraryPage` 壳层),三页对应轻量重构为 `XxxList` 展示组件 —— 仅当视觉/重复确实需要时才做(YAGNI)。

### 模型复用

- 卡片 Tab 直接复用 `pages/queryAssetCenterModel.ts`(`normalizeQueryAssets` / `filterQueryAssets` / `buildQueryAssetTabs`),无需新模型。
- 资产库总览的「看板数 / 卡片数」计数(对应 spec §4 首屏「📌 我的资产」卡)可由 `listDashboards().length` + `listCards().length` 得到;如需统一,新增轻量 `assetLibraryModel.ts` 汇总计数(可选)。

### 三类资产呈现

| Tab | 数据 | 复用 |
|-----|------|------|
| 看板 | `listDashboards()` | `DashboardsPage` |
| 卡片 | `listCards()` + `listAnalysisDrafts()` | `CardsPage` + `queryAssetCenterModel` |
| 集合 | `listCollections()` | `CollectionsPage` |

## 影响范围

- 新增 `src/pages/AssetLibraryPage.tsx`(壳 + Tab + URL 同步)。
- 复用(原则上不改逻辑):`pages/DashboardsPage.tsx`、`pages/CardsPage.tsx`、`pages/CollectionsPage.tsx`、`pages/queryAssetCenterModel.ts`。
- 路由注册(F1/导航):`/assets` 指向 `AssetLibraryPage`;旧的 `/dashboards`、`/questions`、`/collections` 一级菜单按 D5 降级(是否保留旧路由可达由导航 Feature 决定,本 Task 不删旧组件)。
- 可选新增 `src/pages/assetLibraryModel.ts`(资产计数汇总)。
