# T01: 存为卡片

**优先级**: P1
**状态**: READY
**依赖**: F4 画布(提供 `CanvasActions` 动作行与「当前产物」)、F5 回答(产物携带 spec / SQL / 命中口径)

## 目标

让画布「当前产物」一键存成正式卡片(question):点击动作行 `[存为卡片]` → 弹命名 + 选集合的轻量表单 → 调后端建卡片接口,把产物的查询 spec、生成 SQL、命中口径写入卡片;成功后给出可跳转到资产库/卡片详情的反馈。

## 技术设计

### 数据来源(画布当前产物)

由 F4/F5 定义的产物对象提供以下字段(本 Task 只消费,不定义产物结构):

- 产物标题建议 / 原始问题文本(作为卡片命名默认值)
- 查询 spec(dataset / 维度 / 度量 / 过滤,对应可重放查询)
- 生成 SQL(`sql` 文本)
- 命中口径与版本(口径芯片数据,写入卡片描述或扩展字段,保证可溯源)
- 展示类型 `display`(table / bar / line / pie / scalar)

> 若产物来自 Copilot 草稿(draft),优先走草稿晋升路径(见下「两条落库路径」)。

### 接口签名(均已存在,真实)

```ts
// src/api/modules/card.ts
analyticsApi.listCollections(): Promise<CollectionListItem[]>            // GET  /api/analytics/collection
analyticsApi.createCard(body: unknown): Promise<CardDetail>             // POST /api/analytics/card
analyticsApi.saveAnalysisDraftCard(id): Promise<AnalysisDraftSaveCardResponse> // POST /api/analytics/analysis-drafts/{id}/save-card → { draft, card }
```

### 两条落库路径

1. **产物有关联 draftId(Copilot 草稿来源)**:优先调 `saveAnalysisDraftCard(draftId)`,复用后端已有的「草稿转正式卡片」逻辑(口径/SQL 已在草稿里),返回 `{ card }` 即为新卡片;命名/集合若与默认不同,再 `updateCard` 修正。
2. **产物无 draftId(即席结果)**:本地组装卡片 payload 调 `createCard(body)`。payload 组装函数应抽成纯函数 `buildCardPayloadFromArtifact(artifact, { name, collectionId })`,便于单测,产出形如:
   - `name`、`collection_id`、`display`
   - `dataset_query` / `sql`(来自产物 spec / SQL)
   - 口径与溯源信息写入 `description` 或约定的扩展字段(与 F5 产物结构对齐)

### UI 交互

- 在 F4 画布动作行接入 `onSaveCard` 回调;由 F7 提供一个 `<SaveCardModal>`(复用 `ui/Modal`、`ui/Input`、`ui/Input/Select`):
  - 名称输入(默认填产物标题/问题)
  - 集合下拉(`listCollections()` 拉取;默认 root)
- 提交态/错误态走现有 `ErrorNotice` + 按钮 loading 样式;成功后 toast/卡片提示并给「打开卡片」链接(`/questions/{id}`,与 `queryAssetCenterModel` 的 href 约定一致)。
