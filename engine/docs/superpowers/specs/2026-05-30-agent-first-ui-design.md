# dts-copilot 前端重构设计:Agent-First 单入口智能交互系统

- 日期:2026-05-30
- 状态:设计已确认,待评审 → 进入实施计划
- 范围:dts-copilot-webapp 前端为主,涉及 dts-copilot-ai / adminapi / analytics 后台增量

---

## 1. 背景与问题

后台建模(本体、NL2SQL、报花域语义层)已就绪,但前端把「问数据」这件事切成了互不相通的孤岛,导致 NL2SQL 名义可用、实际不好用。

诊断出三个结构性问题:

1. **入口碎片化**:同一诉求散落在 6+ 个路由 —— `/agent-bi`、`/analyze`、`/explore-sessions`、`/report-factory`、`/fixed-reports`、`/metric-lens`,外加一个浮动的 `CopilotSidebar`。用户进来不知道该去哪问。
2. **两个平行世界**:Metabase 范式 BI(collections/dashboards/questions/data/models/metrics/screens)与浮动 Copilot 聊天互不交接。聊天问出的结果存不进看板;BI 里的卡片不能拿去追问。
3. **NL2SQL 四个卡点**:冷启动不知道能问什么;问一句断一句无法追问;结果出来回到 BI 要重来;看不到用了哪张表/口径,不可信。

## 2. 设计目标与定调

**系统对外只有一个入口,它就是 agent。** 看板、固定报表、卡片不再是并列菜单项,而是 agent 在对话里能调用/产出的能力之一。前端从「BI 工具 + 聊天插件」转变为「agent 工作台,BI 是它的产物」。

## 4. 整体形态与布局

唯一入口 = 一个 agent 工作台,两个状态:

### 状态一 · 冷启动首屏(空对话)
- 居中一个大输入框(支持语音),占位「问一句,或说一句…」。
- 起手芯片:高频问题(本月各项目利润、报花趋势)+ 固定报表入口(「打开报花月报」)。
- 三张卡:
  - ⚠ **主动信号**(如「华东区报花环比 −18%,要看吗?」)
  - ↻ **继续上次**会话
  - 📌 **我的资产**(看板数 / 卡片数)

### 状态二 · 进入分析(对话脊柱 + 活产物画布)
- **极细左导航**(4 个一级图标):＋新对话 · 💬历史会话 · 📁资产库 · 🔔信号;管理员右上角多一个 ⚙治理后台。
- **中间:对话脊柱**(约 40% 宽)—— 连续对话,展示分析脉络;消息内含常驻可改口径芯片、推荐追问条;底部语音/文字输入框。
- **右侧:活产物画布**(剩余宽)—— 钉「当前在看的产物」;顶部动作:[存为卡片] [钉到看板] [</> SQL·溯源] [导出];底部为会话产物托盘(历史产物收纳)。

## 5. 信息架构收口

旧入口不删功能,而是各归三处:

- **A · 折叠为「对话能力」**(agent 工具,前台无独立页)
  - `/metric-lens` → 口径/指标解释,对话随问随调
  - `/fixed-reports` 运行 → 起手芯片 / 对话指令
  - `/analyze`、`/agent-bi` 向导 → 化进冷启动首屏 + 推荐追问
- **B · 沉淀为「资产类型」**(📁资产库二级入口)
  - `cards` / `dashboards` / `screens` → 资产库浏览管理
  - `/report-factory` → 退化为对话里「存为报表/看板」动作 + 资产库模板区
  - 固定报表定义 → 资产库「官方报表」分组,可被对话引用
- **C · 保留为「治理后台」**(管理员,非前台主线)
  - `data` / `models` / `metrics` 建模 → 本体/语义层维护
  - `admin/settings/copilot`、`admin/users` → 设置

**收口后一级入口仅 4 个**(见上)。旧业务路由直接删除、彻底重构。**例外:** `/public/*` 三类外发分享链接保留可访问。

## 6. 对话完整回路 + 溯源信任

**闭环六步**(每步可继续、可回退、可沉淀):
🎙 提问 → 🧠 本体匹配口径 → ⚡ 乐观出结果 + 假设芯片 → 🔍 溯源可展开 → ↘ 推荐追问 → 📌 存为资产。

**结果卡**:常驻口径芯片(D8)+ 图表/表格 + 动作行(存卡片/钉看板/溯源/导出)。

**溯源面板**(把现有 `TracePanel` 扶正为一等公民):命中口径(来自本体,含口径版本)、数据来源(表/字段)、生成 SQL、「⚑口径不对?纠正」。

**两个"更智能"的机制:**
1. **推荐追问引擎**:每个结果后,agent 基于本体维度自动生成下钻建议(按区域拆 / 环比 / TOP5 / 看异常),降低 NL2SQL 冷场。
2. **纠正即学习**:溯源里一键纠正口径,回流到 NL2SQL 评测集 / 本体草稿(对接 sprint-26 adminapi 写回桩),agent 越用越准。

## 7. 主动洞察 & 本体探索

两项都长在同一条对话脊柱上,不另开页面,复用同一套消息/画布/溯源组件。

### ③ 主动洞察 / 异动预警(完整版,D9)
- **产出**:后台按本体维度跑监控(环比/同比/阈值/异常检测)→ 产出信号 → 写入信号库。
- **呈现三处递进打扰**:🏠 首屏信号卡 → 🔔 信号入口(全部信号 + 订阅管理) → 🔴 角标提示(不弹窗打断)。
- **点信号 = 直接起一条对话**(已下钻到对应维度,给趋势 + 可能原因,问是否继续)。

### ④ 本体 / 口径探索
- 用户问「我有哪些数据 / 报花指什么 / 利润口径怎么算」。
- 画布产出**可点的「本体地图」**(非死文档):域—实体—指标节点,显示口径定义、版本、关联表数;点任一节点 →「就用它问一个」。
- 价值:让新手先「看见有什么」再开口,治冷启动。

## 8. 技术落点

不是从零写。核心工作是「把浮动聊天扶正成主界面」+ 拆解 1379 行的 `CopilotChat` + 新增画布/信号/本体三块。

### 复用(已有,改造接入)
- `CopilotChat`(1379 行,**超 800 行需拆分**为:对话线程 / 消息渲染 / 输入器 / 画布 / 产物托盘)→ 对话脊柱
- `copilotSse` → 流式输出
- `TracePanel` → 溯源面板(扶正)
- `VoiceInputButton` → 语音入口
- `InlineSqlPreview` → SQL 预览
- `FeedbackButtons` / 纠正 → 回流评测
- `analyticsApi` / 资产接口 → 存卡片/看板
- 后台本体 / NL2SQL agent(已建)

### 新建
- **前端**:活产物画布 + 产物托盘(核心新件)、冷启动首屏、常驻假设/口径芯片组件、推荐追问条、本体地图画布产物。
- **后台**:追问建议引擎(本体维度)、本体地图 API、主动监控 job + 异常检测 + 信号库、action framework 桩接口(⑤预留)。

### 模块边界原则
- 每个单元单一职责、通过明确接口通信、可独立测试。`CopilotChat` 拆分后单文件控制在 800 行内。
- 画布(产物渲染)与对话(消息流)解耦,通过「产物引用」接口连接 —— 消息持有产物 id,画布按 id 渲染当前产物。

## 9. 分期(各期可独立上线、各自闭环)

- **P1 · 核心骨架(MVP)— 能力 ①②**
  对话脊柱 + 活产物画布扶正为主界面 · 冷启动首屏 · 乐观 NL2SQL + 口径芯片常驻 · 溯源面板 · 存卡片/看板 · 删旧路由彻底重构(保留 `/public/*`)。上线即「一个入口能问数能沉淀」。
- **P2 · 智能增强 — 能力 ④⑥**
  推荐追问引擎 · 本体探索地图 · 纠正即学习回流评测集 · 固定报表**完整承接**(起手模板区 + 资产库「官方报表」分组 + 对话引用)。
  > 注:P1 冷启动首屏可先放一个「打开报花月报」的简单跳转芯片;⑥ 的完整承接(模板化、对话内引用)在 P2 完成。
- **P3 · 主动 + 预留 — 能力 ③⑤**
  完整版主动洞察(后台监控 + 异常检测 + 信号调度 + 订阅) · action framework 桩接口 · 语音体验强化。

## 10. 范围边界与风险

- **YAGNI**:⑤ 写回/执行本期只留桩接口,不实现任何实际写动作及其确认流/安全流;真正需要时再单独走 spec。
- **多产物平铺**不做(D6),如后续有强需求再议。
- **风险点**:
  - `CopilotChat` 1379 行重构风险高,需先建测试护栏再拆。
  - 彻底重构删旧路由会影响现有用户习惯与书签;`/public/*` 已保留,其余需在发布说明中告知。
  - 完整版主动洞察依赖后台调度与检测能力,P3 工作量最大,需评估异常检测算法选型。
